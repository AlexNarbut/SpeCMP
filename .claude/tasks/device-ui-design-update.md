# Выбор устройства и расширенный монтаж: доработки по новому дизайну

**Статус:** план одобрен 2026-10-13. Этапы 1–5 и SDK 2.0.95 закоммичены, этап A сделан; дальше B–G.

## Решения пользователя (2026-10-13)

1. Состояния «пусто» нет: если возможности не прочитаны, показываем «не поддерживается» с базовыми разделами.
2. Чат из монтажа открывает существующую фичу `support-chat`.
3. Метка режима («Сопряжение» / «Загрузчик») **остаётся в карточке списка в широкой раскладке (split)**. В compact и
   stacked её нет, режим виден в диалоге «⋮».
4. Иконки разделов — **новые из макета**, а не legacy SVG (подробности в этапе E.6). Заблокированные плитки делаем
   точно как в макете (этап E.2).
5. Тип подключения отдаёт `DeviceSession`.
**Ветка:** `feature/device-connection`, поверх этапов 1–5 из `device-interaction-flow.md` (не закоммичены).

**Дизайн:**
- `design/features/device-select/DeviceSelect.jsx`;
- `design/features/advanced-mount/AdvancedMount.jsx`;
- `design/changelog/2026-10-13-device-select.md` и `design/changelog/2026-10-13-advanced-mount.md`.

**Требования к старому экрану:** `.claude/tasks/advanced-mount-legacy-ui.md`.

## 1. Что есть и чего не хватает

### Выбор устройства (`feature/device/selection-ui`)

| Элемент | Сейчас | По дизайну |
|---|---|---|
| Иконка в карточке | 56 / 60 | 44 (compact) / 48 (stacked, split); высота строки около 64 |
| Первая строка | имя + systemId (USB) | имя; у BLE справа RSSI `-67 dBm` (моноширинный) |
| Вторая строка | чип «Bluetooth/USB» + адрес (`производитель · VID:PID` у USB) | чип **«BLE»** / «USB»; BLE — MAC; USB — `systemId`, а если его нет, `HID · VID:PID` |
| Третья строка | тип · RSSI / прошивка + метка режима | **нет** (всё в деталях) |
| Детали в compact и stacked | нет, нажатие сразу подключает | кнопка «⋮» (48 dp) → диалог с полями и кнопками «Закрыть» / «Подключить»; нажатие на строку по-прежнему подключает |
| Панель деталей (split) | фото, имя, чип, метка режима, строки | фото 128, имя, чип с полным названием, строки, сноска для BLE, «Подключить» |
| Строки BLE | MAC, тип, режим, сигнал, связь | «MAC-адрес» (iOS — «ID (UUID)»), «Тип устройства», «Уровень сигнала», «Режим», «Связь с телефоном» (только Android), «Связь у самого устройства» |
| Строки USB | ID блока, производитель, VID:PID, прошивка, режим | «ID блока (systemId)» (нет — «не определён»), «Производитель», «VID:PID», «Версия прошивки», «Режим» |
| Выделение режима | цветная метка | в строке «Режим» значения «Сопряжение» и «Загрузчик» — жирным, акцентным цветом |
| Сноска BLE | нет | «Версия прошивки и ID блока в эфире не передаются — они появятся после подключения.» |
| Прошивка | `VER3.57` | `3.57` |

Состояния экрана уже совпадают с дизайном: разрешения, отказ, Bluetooth выключен, поиск, пусто, подключение с
«Отменой». Поток подключения → «Расширенный монтаж» тоже совпадает.

### Расширенный монтаж (`feature/advanced-mount`, `feature/device/interaction-ui`)

Сейчас есть только простая шапка, сетка из 6 разделов по возможностям блока и заглушки разделов. По дизайну нужно:

**Верхняя панель**
- «Расширенный монтаж», стрелка назад.
- Справа пульсирующая иконка «Удалённая синхронизация». Видна, только если сервер разрешает удалённый монтаж.

**Шапка блока** (карточка)
- Фото-заглушка 56 / 72, название (акцентом), «ID …».
- Чипы: тип подключения (Bluetooth / USB) и «Режим: Рабочий / Загрузчик».
- Строки:
  - «Версия ПО»;
  - «Версия ПО CAN» и «CAN код» с пульсирующим ⚠ (только у блоков с отдельной CAN-прошивкой). Нажатие на ⚠ открывает диалог-подсказку «Прошивка CAN» / «Понятно»;
  - «IMEI GSM модема» (если прочитан).
- Кнопка «Информация о товаре» с обводкой (если у пользователя включён поиск товара).

**Сетка разделов**
- 10 разделов вместо 6. Добавить «Заявки на техпомощь», «Чат техподдержки», «Заявки народных карт», «Автомобили».
- Правила показа как в старом приложении:
  - «Заявки на техпомощь» и «Заявки народных карт» — при поддержке настроек;
  - «Чат техподдержки» и «Автомобили» — всегда.
- Плитка: иконка 52 на `primaryContainer`, заголовок, подзаголовок в 2 строки, шеврон.
- **Замок.** Если CAN-настройки заводские, у «Расширенных настроек», «Бесключевого обхода», «Процедуры Clone» и «Доп. устройств»:
  - на иконке бейдж-замок, вместо подзаголовка жирным «Сначала обновите CAN-прошивку»;
  - нажатие открывает диалог «Внимание» с кнопками «Отмена» и «Перейти к обновлению» (перевод блока в загрузчик).
- **Непрочитанные в чате:** бейдж с числом на иконке, другой текст плитки («Чат тех. поддержки» / «Напишите в чат…»).

**Раскладка**

| Класс окна | Раскладка |
|---|---|
| Compact < 600 | шапка сверху, плитки в 1 колонку |
| Medium 600–839 | шапка сверху, сетка в 2 колонки |
| Expanded ≥ 840 | слева шапка (340), справа сетка в 2 колонки, max-width 1180 |

**Состояния области сетки** (шапка видна всегда)

| Состояние | Что показываем |
|---|---|
| загрузка | спиннер + «Читаем возможности блока и проверяем его на сервере…» |
| ошибка проверки | «Не удалось проверить блок на сервере», кнопка «Исправить» |
| доступ запрещён | «Доступ ограничен данному устройству», причина от сервера, кнопка «Повторить» |
| не поддерживается | красная плашка + 3 базовых раздела |
| ~~пусто~~ | не делаем (решение 1) |
| готово | сетка разделов |

**Потеря связи** (поверх монтажа)
- Иллюстрация `svyaz_poteryana`, «Отсутствует соединение с устройством».
- Текст зависит от канала:
  - USB: «Проверьте USB соединение с устройством.»;
  - BLE: «Блок выключен или находится далеко…».
- Строка «Ждём возвращения блока…» со спиннером, кнопка «Отключиться» с обводкой (выход из flow, как «Назад»).

**Заглушки разделов:** подзаголовок «Название  ID».

**Не проработано в дизайне:** экран загрузчика, «Информация о товаре», «Удалённая синхронизация». Оставляем заглушками.

## 2. Данные: всё есть в SDK 1.2.0

| Нужно | Откуда |
|---|---|
| CAN: версия, код, заводской ли | `AlarmDeviceInformation.canInformation` (`canVersionString`, `canCode`, `isFactoryCanSettings`); показывать при `SubsystemFeature.SINGLE_CAN_FIRMWARE` |
| IMEI | `getModemInformationUseCase` → `imei` |
| Проверка блока на сервере | `VerifyDeviceUseCase(systemId, systemName, firmwareVersion)` → `hasAccess`, `message` |
| Перевод в загрузчик | `setAlarmDeviceBootModeUseCase`; в старом приложении команда повторялась через 3 с |
| Непрочитанные в чате | `GetUnreadMessagesCountUseCase`, опрос раз в 60 с |
| Удалённый монтаж | `IsAvailableRemoteMountFlowUseCase`; перед ним `openChatUseCase` |
| «Информация о товаре» | `GetUserAppFeaturesUseCase` → `UserAppFeature.PRODUCT_SEARCH` |
| Тип подключения | известен при подключении (`ConnectedDevice.transport`) |

## 3. План реализации

### Этап A. Выбор устройства: карточка и детали (только UI)

Файлы: `DeviceUiItem.kt`, `DeviceSelectContent.kt`, `DeviceSelectionScreen.kt`, строки ru/en.

1. `DeviceRow`:
   - размер иконки 44 / 48;
   - RSSI справа в первой строке;
   - чип «BLE» / «USB»;
   - BLE: MAC; USB: `systemId`, а без него `HID · VID:PID`;
   - убрать третью строку; метку режима оставить только в раскладке split (решение 3);
   - параметр `onInfo`: кнопка `MoreVert` 48 dp в compact и stacked.
2. Новый `DeviceInfoDialog` (`CmpDialog`): название, строки полей, сноска BLE, кнопки «Закрыть» и «Подключить». В
   «Подключить» вызывается тот же `onDeviceSelected`. Открытый диалог — UI-состояние экрана (`rememberSaveable` по
   `id`). VM не трогаем.
3. Общая функция строк деталей `deviceInfoRows(item, platform)`: используется в `DetailPanel` и в диалоге.
   - Лейбл MAC на iOS — «ID (UUID)».
   - «Связь с телефоном» — только когда `hasPhoneBond != null`.
   - Строка «Режим» с выделением для «Сопряжение» / «Загрузчик».
   - USB без systemId — «не определён».
4. `DetailPanel`: убрать метку режима из заголовка, чип с полным названием, сноска BLE.
5. Прошивка: срезать префикс `VER` (`firmwareVersion.removePrefix("VER")`) в `DeviceUiItem`.
6. Строки: «BLE», «⋮»-описание, лейблы, «не определён», «есть» / «нет», сноска, «Закрыть». Удалить ставшие ненужными
   (`device_select_firmware_short` и т. п.).

### Этап B. Данные блока: CAN, IMEI, тип подключения

Модули `feature/device/interaction`, `feature/device/selection-ui`, `composeApp`.

1. `AlarmDevice`:
   - добавить `can: CanInfo?` (`firmwareVersion`, `code`, `isFactory`), заполнять только при `SINGLE_CAN_FIRMWARE`;
   - `features: Set<DeviceFeature>?`: `null` — возможности не прочитаны (сейчас ошибка превращается в `emptySet`).
     Это нужно, чтобы различать «не поддерживается» и «пусто».
2. `firmwareVersion` в модели без префикса `VER` (та же функция, что в этапе A, лежит в `interaction`).
3. `DeviceSessionRepository.readImei(): Response<String?>`. Читается отдельно и не блокирует `Ready`.
4. `DeviceSessionRepository.setBootMode(): Response<Unit>`.
5. Тип подключения:
   - `DeviceConnectionRepository` запоминает транспорт успешного подключения;
   - `DeviceSession` отдаёт его в `Ready`, а также в `Disconnected` и `Connecting` (нужен экрану потери связи);
   - вариант без состояния в репозитории — передавать в `AdvancedMountRoute(transport)`. Выбор — вопрос 5.

### Этап C. Серверная часть монтажа

Модуль `feature/advanced-mount`: свои `domain` и `data`, узкие зависимости на SDK, как в других фичах.

1. `AdvancedMountRepository`:
   - `verify(device): Response<DeviceAccess(hasAccess, message)>`;
   - `unreadChatCount(): Response<Int>`;
   - `remoteMountAvailable(): Flow<Boolean>` (внутри `openChat`);
   - `isProductInfoEnabled(): Response<Boolean>`.
2. Реализация через use case-ы specialist SDK. Регистрация в `advancedMountModule`.

### Этап D. Главный экран монтажа: модель и VM

1. `MountSection`:
   - добавить `TECH_REQUESTS`, `SUPPORT_CHAT`, `COMMUNITY_MAPS`, `VEHICLES`;
   - поле `needsCan` для `SETTINGS`, `BYPASS_LEARNING`, `CLONE`, `DYNAMIC_DEVICES`;
   - `toSections(features)` по правилам из п. 1;
   - fallback для «не поддерживается»: прошивки, чат, автомобили.
2. `AdvancedMountRootState`:
   - `device`, `imei`, `transport`;
   - `content: Loading | VerifyError(message) | Denied(message) | Ready(sections, unsupported)`;
   - `canLocked`, `unreadCount`, `remoteAvailable`, `productInfo`.
3. `AdvancedMountRootViewModel` через `DeviceScope`, на готовом блоке:
   - IMEI;
   - проверка на сервере → разделы;
   - опрос непрочитанных раз в 60 с;
   - подписка на удалённый монтаж (после успешной проверки);
   - флаг «Информации о товаре».
   Повтор (кнопки «Исправить», «Повторить») перезапускает цепочку.
4. Действия:
   - `onSectionClick`: для заблокированной плитки — `Effect.ShowCanDialog`, иначе навигация;
   - `onCanUpdateConfirm()` → `setBootMode` (с повтором через 3 с, как в старом коде) → блок переподключается в
     загрузчике → host показывает экран загрузчика;
   - `onCanHint` → диалог-подсказка;
   - `onRemoteSync`, `onProductInfo` → заглушки.
5. Чат техподдержки: плитка открывает существующую фичу `support-chat` через колбэк `AdvancedMountNavGraph`
   (`onOpenSupportChat`) в `composeApp`. Остальные новые разделы — заглушки.

## 4. Открытые вопросы

1. **«Пусто» и «Чат» / «Автомобили».** Чат и автомобили показываются всегда, поэтому сетка никогда не бывает пустой.
   Варианты:
   - (а) «пусто» — только если блок вернул пустой набор возможностей, и тогда чат и автомобили скрываем;
   - (б) состояние «пусто» не делаем.
   Предлагаю (б): показывать «не поддерживается» с базовыми разделами.
2. **Чат техподдержки** из монтажа: открывать существующую фичу `support-chat` (предлагаю) или пока заглушкой?
3. **Карточка в списке:** убрать метку режима и тип из списка, как в дизайне? Тогда «Загрузчик» виден только в деталях.
   Предлагаю следовать дизайну.
4. **Иконки разделов:**
   - сейчас legacy SVG, потом замена на новые (дизайнер ещё рисует) — предлагаю так;
   - или сразу взять те, что в макете (часть из главной `main_*`, часть в JSX-путях).
5. **Тип подключения на экране потери связи:**
   - через `DeviceSession` (репозиторий помнит транспорт последнего подключения) — предлагаю этот вариант, так
     быстрый монтаж получит его бесплатно;
   - или параметр маршрута `AdvancedMountRoute(transport)`.
6. **Порядок этапов.** Можно разбить на две поставки:
   - A (выбор устройства);
   - B–G (монтаж).
   Предлагаю сначала закоммитить этапы 1–5 и SDK 2.0.95, потом A, потом B–G.
