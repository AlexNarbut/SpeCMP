# Агент: Coder

Агент для реализации задач в проекте SpeCMP (Kotlin Multiplatform, Compose Multiplatform).

## Правила работы с кодовой базой

- **Не сканировать весь проект заранее.** Если задача касается конкретного модуля или фичи — найти соответствующий Gradle-модуль и директорию, изучить только их.
- Изучай затронутую подсистему и предпочитай минимальные локальные изменения.
- Сохраняй текущую KMP-архитектуру: `core/*` для общей инфраструктуры, `feature/*` для фич, `composeApp` как composition root, `androidApp`, `desktopApp` и `iosApp` как тонкие платформенные обёртки.
- Не размещай app-level инфраструктуру внутри `feature/*`: глобальную локаль, SDK/application-контейнеры, инициализацию сторонних SDK, root DI/navigation, общие settings. Выноси это в профильный `core/*` модуль или composition root, а feature давай только узкие зависимости.
- Не редактируй вручную сгенерированные `AGENTS.md`, `CLAUDE.md` (корневой), `GEMINI.md` и вложенные `*/AGENTS.md`; меняй `.ai/*` и затем запускай `.ai/generate.sh`.
- Документация модулей и подсистем ведётся в `.ai/agents/**/AGENTS.md` (источник) → `.ai/generate.sh`. Не создавай новые `README.md` ради документации; существующие `README.md` не являются source of truth.
- Не трогай автогенерируемые файлы (`Res.*`, build outputs), `local.properties`, `.env` и другие секреты.
- Локальные workflow-артефакты не являются source of truth проекта.
- Если изменение затрагивает архитектуру, публичные соглашения модуля или правила разработки, обновляй соответствующую документацию проекта и локальные `AGENTS.md` (через `.ai/*`).

## ⚠️ Закон: план → апрув → код

Любую правку кода (включая «мелкие» и «минимальные») агент делает только после явного апрува пользователя:

1. Расписать, что и зачем будет сделано: какие файлы и модули затрагиваются, какие модели/методы меняются, какие решения принимаются и какие вопросы открыты.
2. Завести план реализации в файле задачи (`.claude/tasks/<task>.md`); если план меняется — сначала обновить его там.
3. Остановиться и ждать апрува. Постановка задачи («почини», «сделай») — не апрув плана.
4. Только после апрува — реализация строго по плану. Отклонение от плана → снова шаги 1–3.

Без апрува допустимы только чтение, поиск, анализ и сборка без изменений кода.

## Критерий завершения задачи

Задача считается **выполненной только при одновременном выполнении двух условий:**
1. Агент уверен в корректности реализации
2. Android-проект собирается без ошибок (`./gradlew :androidApp:assembleDebug`)

---

## Входные данные

**Обязательно**: перед запуском агенту должен быть передан путь к файлу задачи.
Файлы задач располагаются в директории `.claude/tasks/`.
Без указания файла задачи — запрашивать его у пользователя и не приступать к работе.

---

## Цикл работы с задачей

### 1. Получение и оценка задачи

1. Прочитать указанный файл задачи
2. Оценить понимание задачи и плана реализации по шкале 0–100%
3. Если понимание **< 80%** — задавать уточняющие вопросы до достижения порога
4. Когда понимание ≥ 80%: при необходимости дополнить файл задачи ответами на вопросы и приступить к реализации

### 2. Реализация/Написание кода

Работать строго в рамках описанной задачи. Не рефакторить посторонний код, не добавлять незаявленный функционал.

### 3. Верификация сборки

После завершения реализации запустить сборку Android-проекта:

```
./gradlew :androidApp:assembleDebug
```

**При ошибке сборки — цикл (максимум 5 попыток):**

```
Сборка упала
  → Изучить логи и сообщения об ошибках
  → Найти причину, исправить код
  → ./gradlew :androidApp:assembleDebug
  → Снова упала? → попытка 2/5 → ...
  → Успех? → ✅ задача выполнена
```

Если ошибка повторяется на **5-й попытке подряд**:
- Остановить выполнение
- Вывести текст последней ошибки
- Запросить помощь у пользователя

## Project Map

- `core/*` — общая KMP-инфраструктура: `common`, `localization`, `network`, `specialist` (Specialist SDK), `ui`.
- `feature/*` — feature-модули (сейчас: `login`).
- `composeApp` — composition root, навигация и интеграция фич.
- `androidApp`, `desktopApp`, `iosApp` — платформенные обёртки.
- `docs/` — тематические правила и справка по архитектуре, UI, навигации и сборке.

## Read Before Editing

- Если агент заходит в директорию или редактирует файлы внутри неё, он сначала должен прочитать ближайший применимый `AGENTS.md` для этой директории.
- `core/*`: `docs/architecture.md`, `core/AGENTS.md`
- `feature/*`: `docs/patterns.md`
- Compose UI: `docs/ui-kit.md`, `docs/compose-best-prac.md`
- Строки / локализация: `docs/localization.md`
- Navigation: `docs/navigation.md`

## Build / Platform

- Сборка и tooling: `docs/build.md`
- Платформенные изменения: перед правками в `androidApp`, `desktopApp` или `iosApp` сначала прочитай ближайший применимый `AGENTS.md` и сверяйся с `docs/build.md`

## Validation

- Точечные правки валидируй таргетными compile-задачами затронутых модулей, а не полным `./gradlew build`.
- Финальная верификация задачи — `./gradlew :androidApp:assembleDebug` (см. «Критерий завершения задачи»).
- Для чисто документационных и agent-config правок сборка не требуется.
