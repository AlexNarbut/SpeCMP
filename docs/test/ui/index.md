# UI-тестирование агентами (скилл `ui-test`)

Агент (Claude Code, Codex, Kimi Code, Gemini CLI) по описанию фичи составляет тест-план, прогоняет кейсы на
Android-эмуляторе, iOS-симуляторе и/или desktop (macOS), пишет ревью и задачу для агента-кодера.
Код приложения скилл не меняет.

| Документ | О чём |
|---|---|
| [ui-sh.md](ui-sh.md) | `ui.sh` — CLI управления устройством: команды, селекторы, логи, Maestro |
| [platforms.md](platforms.md) | требования и особенности Android / iOS / Desktop |
| [authoring.md](authoring.md) | как устроен скилл, где источник, как править и раскладывать по агентам |

## Быстрый старт

1. Креды тестового аккаунта (файл в `.gitignore`):
   ```bash
   cp .agents/skills/ui-test/credentials.properties.example .agents/skills/ui-test/credentials.properties
   # заполнить QA_EMAIL, QA_PASSWORD (только ASCII)
   ```
2. Проверка окружения — для каждой нужной платформы:
   ```bash
   .agents/skills/ui-test/scripts/ui.sh doctor android   # ios | desktop
   ```
   Каждый ❌ выводит команду исправления. Требования — [platforms.md](platforms.md).
3. Запуск в агенте:

   | Агент | Вызов |
   |---|---|
   | Claude Code | `/ui-test <описание фичи \| путь к файлу задачи>` |
   | Codex | `$ui-test <…>` или «используй скилл ui-test: …» |
   | Kimi Code, Gemini CLI | «используй скилл ui-test: …» |

   Режимы: `ui-test rerun .ai-qa/<slug>` — повторная проверка после доработок, `ui-test continue .ai-qa/<slug>` —
   продолжить прерванный прогон.

## Как проходит прогон

Оркестратор (основной агент) общается с пользователем и раздаёт работу субагентам:

| Шаг | Кто | Результат |
|---|---|---|
| 0. Платформы | оркестратор | вопрос: Android / iOS / Desktop (любая комбинация) |
| 1. Окружение | оркестратор | `ui.sh doctor <platform>` до `OK` |
| 2. Сборка | оркестратор | Android/iOS: `use` → `build` → `install`; Desktop: `use` → `build` → `launch` |
| 3. План | `ui-test-planner` | `plan.md` + `flows/<ID>.yaml` (Maestro, только Android/iOS); **ждёт апрува пользователя** |
| 4. Прогон | `ui-test-runner` | по этапу (3–4 кейса) на платформу, Android → iOS → Desktop → `run.md` |
| 5. Ревью | `ui-test-reviewer` | `review.md`, при необходимости `coder-task.md` |
| 6. Уборка | оркестратор | `ui.sh stop` |

Если инструмент не умеет субагентов, оркестратор выполняет роль сам по `.agents/skills/ui-test/roles/<role>.md`.

## Результаты

Папка теста `.ai-qa/<feature>-<YYYY-MM-DD>/` (не в git):

| Файл | Содержимое |
|---|---|
| `plan.md` | этапы и кейсы: `T` — из задачи, `A` — предложены агентом; P0–P2; шаги и ожидаемое |
| `flows/<ID>.yaml` | Maestro-флоу кейса с проверкой после каждого шага |
| `run.md` | статусы по платформам (✅ ❌ ⚠️ ⏭), отклонения, замечания «попутно», проблемы инструмента |
| `review.md` | вердикт, баги с шагами воспроизведения, UX, тестируемость (каких `testTag` не хватает) |
| `coder-task.md` | задача для агента-кодера с приёмкой по ID кейсов; передаётся как файл задачи |
| `shots/`, `logs/` | скриншоты и логи к ❌/⚠️ |

Правила оформления документов — `.agents/skills/ui-test/templates/RULES.md`.

## Правила

- Креды не попадают ни в чат, ни в документы: только ключи (`<QA_EMAIL>`); `ui.sh` подставляет значения сам.
- Прогон без апрува плана не начинается.
- Проблемы `ui.sh` / Maestro / устройства фиксируются в `run.md` → «Инструмент», а не как баги приложения.
- Тестируемость: `testTag` есть только на части экранов (подключение к устройству — см. `feature/device/AGENTS.md`), остальное
  ищется по тексту. Недостающие теги ревьюер выносит в «Тестируемость» и `coder-task.md`.
