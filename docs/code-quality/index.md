# Качество кода: инструменты статического анализа

Раздел описывает инструменты, которые подключены к SpeCMP, чтобы неиспользуемые импорты, неверное именование и небезопасный код ловились автоматически, а не только прогонами агентов.

> Статус: справочник по инструментам. Актуальная конфигурация, версии, архитектура вызова и принятые решения —
> в [`../code-quality.md`](../code-quality.md); при расхождении верен он.

## Документы

| Документ | О чём |
|---|---|
| [`spotless.md`](spotless.md) | Gradle-оркестратор форматтеров: `spotlessCheck` / `spotlessApply`, ratchet по git |
| [`ktlint.md`](ktlint.md) | Стиль и форматирование Kotlin: импорты, именование, `.editorconfig` |
| [`detekt.md`](detekt.md) | Статический анализ: code smells, баги, именование пакетов/классов, кастомные правила |
| [`compose-rules.md`](compose-rules.md) | Правила для Compose поверх ktlint или detekt |

## Как инструменты соотносятся

```
                ┌───────────────┐
                │   Spotless    │  запускает и применяет (Gradle)
                └───────┬───────┘
                        │ использует как движок
                ┌───────▼───────┐        ┌───────────────┐
                │    ktlint     │◄───────│ compose-rules │  (ktlint-вариант)
                └───────────────┘        └───────┬───────┘
                                                 │ или
                ┌───────────────┐                │
                │    detekt     │◄───────────────┘  (detekt-вариант)
                └───────────────┘
```

- **Spotless** не содержит правил сам, это способ запускать форматтеры (в т.ч. ktlint) и автоматически чинить.
- **ktlint** отвечает за форматирование и простые стилевые правила, большинство умеет автофикс.
- **detekt** отвечает за анализ смысла (сложность, потенциальные баги, обработка исключений), автофикса почти нет.
- **compose-rules** добавляют правила про Compose к ktlint или detekt (подключается к одному из них, не самостоятельный запуск).

## Что какая проблема закрывается

| Проблема | Кто закрывает | Автофикс |
|---|---|---|
| Неиспользуемые импорты | ktlint (`no-unused-imports`) через Spotless | да |
| Порядок импортов, wildcard-импорты | ktlint (`import-ordering`, `no-wildcard-imports`) | да |
| Формат имени пакета/класса/функции | ktlint (`package-name`, `class-naming`, `function-naming`, `filename`), detekt (`naming`) | нет |
| Пакет не совпадает с директорией | detekt (`InvalidPackageDeclaration`) | нет |
| Файл не совпадает с именем класса | ktlint (`filename`), detekt (`MatchingDeclarationName`) | нет |
| Потенциальные баги, небезопасные касты, `!!` | detekt (`potential-bugs`) | нет |
| Проглоченные исключения | detekt (`exceptions`) | нет |
| Ошибки Compose (`Modifier`, `remember`, стабильность) | compose-rules | частично |
| Свои правила проекта (`runCatching`, запись `MutableStateFlow.value`) | detekt: `Forbidden*`-правила или кастомный RuleSet | нет |
| Секреты, слабая криптография, cleartext-трафик | **вне этих четырёх**: Android Lint, gitleaks, Semgrep | нет |

## Версии в проекте

- Kotlin `2.4.0`, AGP `8.13.2`, Gradle `9.4.1`, Compose Multiplatform `1.11.1` (см. `gradle/libs.versions.toml`).
- Проект мультимодульный KMP (`commonMain`, таргеты `android`, `jvm`, `iosArm64`), это важно для detekt (см. `detekt.md`).

Версии самих инструментов при обновлении **проверять по официальным релизам**: список меняется быстро.
