# Выравнивание макетов по changelog

Цель: привести **локальный** проект к состоянию **выгрузки**, перенося только те изменения,
которые задокументированы в changelog выгрузки и ещё не применены локально.

Контракт проекта: каждая запись в `changelog/` (`<дата>-<экраны>.md`) описывает одно завершённое
изменение и содержит секцию **Файлы:** — это манифест того, что менялось. Changelog — источник
правды о том, какие файлы трогали. Скилл опирается на это поле, а не на «угадывание» по mtime.

---

## 0. Найди выгрузку

| Способ | Где искать changelog выгрузки |
|---|---|
| **zip в `uploads/`** | Распакуй через `run_script`, читай `changelog/*.md` из распаковки |
| **прилинкованная локальная папка** | через `local_*`-инструменты, путь вида `<folder>/changelog/` |
| **другой проект** (есть view-доступ) | `/projects/<projectId>/changelog/` напрямую через `read_file`/`list_files` |

Если непонятно, в каком виде выгрузка, — спроси пользователя. Ниже `EXPORT/` обозначает корень выгрузки.

### Распаковка zip (если выгрузка — архив)
```js
// run_script
const blob = await readFileBinary('uploads/<export>.zip');
// распакуй zip (JSZip и т.п.), вытащи только changelog/ и затем адресно нужные файлы.
```
Не распаковывай весь архив на диск, если он большой.

---

## 1. Сравни changelog (диф)

1. Считай список файлов локального `changelog/` (без `README.md`).
2. Считай список файлов `EXPORT/changelog/` (без `README.md`).

> Работай только с **финальными** записями `<дата>-<экраны>.md` в корне `changelog/`. Бакеты-поддиректории
> (`current/`, `<слаг-фичи>/`) — незавершённые черновики (см. `changelog/README.md`); при диффе
> **игнорируй**: в историю они попадают только после слияния скиллом `merge-changelog`.

3. Раздели по **имени файла** записи:
   - **`new`** = есть в выгрузке, нет локально → основной кейс.
   - **`changed`** = есть в обоих, содержимое отличается.
   - **`local_only`** = есть локально, нет в выгрузке → локаль впереди. **Не трогай.**
   - `same` — игнорируй.

`new ∪ changed` — записи, изменения которых нужно подтянуть.

---

## 2. Построй план переноса файлов

Для каждой записи из `new ∪ changed`:
1. Распарси секцию **Файлы:** — собери пути (проектно-относительные, напр.
   `features/calculator/Calculator.jsx`). Учитывай оба формата (список через `-` и inline через запятую).
   Раскрывай обобщения вида `components/forms/ (… и связанные)` — бери всю папку из выгрузки.
2. **Объедини** все пути в единый набор `files_to_pull`.

### Проверка конфликтов (обязательно перед копированием)
Сопоставь `files_to_pull` с файлами из **`local_only`**-записей. Пересечение = конфликт. Не
перезаписывай молча — перечисли конфликтные файлы и спроси, какую версию оставить.

---

## 3. Перенос

1. Скопируй каждый файл из `files_to_pull` из выгрузки по тому же пути (`copy_files`; для zip —
   `saveFile` из `run_script`). Для бинарников/ассетов — только `copy_files`.
2. Скопируй сами **новые/изменённые записи changelog** (`new ∪ changed`) в локальный `changelog/`.
3. Не удаляй файлы, если запись changelog явно не отмечает удаление в «Что изменилось».

### Подстраховка (если просили «полностью выровнять»)
Сверь ключевые файлы `features/`, `components/`, `res/`, `design-system/` между выгрузкой и локалью.
Расхождения без changelog-записи — **покажи списком и спроси**, переносить ли. Changelog — контракт.

---

## 4. Проверь и отчитайся

1. Открой затронутые макеты (`ready_for_verification` по ключевому HTML) — без ошибок консоли.
   Пути между макетами идут через `window.psGo()` из `res/nav.js`; глубина папок в `features/`
   фиксирована — относительные `../../...` должны сходиться, проверь, что перенос их не сломал.
2. Краткий отчёт: какие записи подтянуты, какие файлы перенесены, конфликты и их разрешение.

## Кратко (happy path)
1. Найти `EXPORT/changelog/`.
2. `new = EXPORT.changelog \ local.changelog`.
3. Из каждой `new`-записи распарсить **Файлы:** → `files_to_pull`.
4. Конфликты с `local_only` → спросить; остальное копировать.
5. Перенести файлы + новые записи changelog по тем же путям.
6. Открыть макеты, проверить консоль, отчитаться.

## Чего не делать
- Не переносить изменения вне changelog-записей без подтверждения.
- Не трогать файлы из `local_only`-записей.
- Не перезаписывать конфликтные файлы молча.
- Не копировать большие папки «на всякий случай» — только то, что в манифесте.
