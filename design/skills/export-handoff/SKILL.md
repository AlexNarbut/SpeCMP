# Выгрузка проекта и хендофф по изменениям

**Флоу целиком:**
1. Пакуем проект в zip — всё кроме `uploads/`.
2. Пользователь распаковывает его локально в свой репозиторий.
3. Дев-агенту передаётся распакованная директория с дизайнами **+ `HANDOFF.md`** — инструкция,
   что именно реализовать (по конкретным экранам/изменениям).

zip всегда полный (кроме `uploads/`), а адресность («делаем только эти экраны») живёт в `HANDOFF.md`,
который ссылается на пути **внутри распакованной директории**.

Перед началом уточни: за какие изменения хендофф (весь набор / конкретные экраны / период по changelog)
и нужен ли git (см. «Бэкап в git»).

---

## Шаг 1. Сгенерируй `HANDOFF.md`

### 1.1. Определи область через changelog
1. Спроси / выведи, какие изменения передаём: по дате (`2026-06-30`), по экрану (`calculator`) или
   диапазон записей.
2. Отбери соответствующие **финальные** записи из корня `changelog/` (бакеты-поддиректории —
   незавершённые черновики, см. `changelog/README.md`; если нужное ещё во фрагментах — предложи
   сперва слить скиллом `merge-changelog`). Из каждой возьми **Что изменилось**, **Зачем**,
   **Заметки** и секцию **Файлы:**.
3. Объедини файлы из секций → `scope_files`. Это макеты-источники истины для дева.

### 1.2. Собери зависимости
Для каждого файла из `scope_files` пройди импорты/ссылки и упомяни в `HANDOFF.md` как референс:
- токены/стили: `design-system/styles.css`, `design-system/tokens/*` (используемые `--*`);
- общие ресурсы: `res/nav.js`, `res/icons/cmp-icons.js` — если задействованы;
- компоненты из `components/**` (их `.prompt.md` и `.d.ts` особенно ценны для дева);
- `features/*/shared/*` части фичи;
- релевантные спеки из `design-system/handoff/`.

### 1.3. Запиши документ
Сохрани в корень проекта как `HANDOFF.md`. Все пути — проектно-относительные. Структура:

```md
# Хендофф: <экраны> — <дата/задача>

Эта папка — распакованная выгрузка макетов Pandora Spec. Реализуй в коде только то, что описано ниже.
Все пути указаны относительно корня этой папки.

## Область (что реализуем)
- <экран/изменение 1>
- <экран/изменение 2>

## Контекст и намерение
<из changelog: «Что изменилось» + «Зачем».>

## Файлы-источники (макеты = истина по UI)
| Путь | Роль | Что взять |
|---|---|---|
| features/calculator/Calculator.jsx | экран калькулятора | разметка, состояния, логика |
| ... | ... | ... |

## Дизайн-система (обязательно соблюдать)
- Токены: design-system/styles.css + tokens/* — только `--*`, без хардкода цветов/размеров.
- Темы: Light / Dark через `data-theme`.
- Иконки: Material Icons (Filled) через каталог CmpIcons (res/icons/cmp-icons.js).
- Зона касания ≥ 48 dp; состояния hover/focus для Desktop.
- Спеки: design-system/handoff/<...> (если есть для этих экранов).

## Зависимости / общие части
<components/**, features/*/shared/*, res/* — где используются.>

## Как смотреть макеты
Открыть HTML-файлы экранов в браузере (автономные React+Babel прототипы во фрейме устройства).
Переключение тем и навигация — внутри `index.html`.

## Чек-лист реализации
- [ ] UI совпадает с макетом в светлой и тёмной теме.
- [ ] Только токены `--*`, без инлайновых цветов.
- [ ] Хит-таргеты ≥ 48 dp, тексты читаемы.
- [ ] Навигация/переходы соответствуют макету.
- [ ] Заметки/ограничения из changelog учтены.

## Не входит в задачу
<явно перечисли смежное, что НЕ нужно менять.>

## Заметки / открытые вопросы
<из changelog «Заметки».>
```

## Шаг 2. Упакуй проект в zip (без `uploads/`)

`uploads/` **не выгружаем** — там исходники для работы агента (спека ДС, референсы). У
`present_fs_item_for_download` нет исключений, поэтому собираем staging-папку и пакуем её:

1. Скопируй в `export/PandoraSpec/` все top-level элементы **кроме `uploads/`** (сверься с актуальным
   `list_files("")`; ориентир: `CLAUDE.md`, `HANDOFF.md`, `index.html`, `styles.css`, `changelog/`,
   `components/`, `design-system/`, `features/`, `res/`, `skills/`, и генерируемые `_ds_bundle.js`,
   `_ds_manifest.json`, `_adherence.oxlintrc.json`):
   ```
   copy_files({ files: [
     { src: 'design-system', dest: 'export/PandoraSpec/design-system' },
     { src: 'components',    dest: 'export/PandoraSpec/components' },
     { src: 'features',      dest: 'export/PandoraSpec/features' },
     { src: 'res',           dest: 'export/PandoraSpec/res' },
     { src: 'skills',        dest: 'export/PandoraSpec/skills' },
     { src: 'changelog',     dest: 'export/PandoraSpec/changelog' },
     { src: 'index.html',    dest: 'export/PandoraSpec/index.html' },
     { src: 'styles.css',    dest: 'export/PandoraSpec/styles.css' },
     { src: '_ds_bundle.js', dest: 'export/PandoraSpec/_ds_bundle.js' },
     { src: 'CLAUDE.md',     dest: 'export/PandoraSpec/CLAUDE.md' },
     { src: 'HANDOFF.md',    dest: 'export/PandoraSpec/HANDOFF.md' },
   ] })
   ```
2. Запакуй staging-папку:
   ```
   present_fs_item_for_download({ path: 'export/PandoraSpec', label: 'Pandora Spec — designs + handoff <дата>' })
   ```
3. Подчисти staging: `delete_file({ paths: ['export'] })`.

Не передавай пустой путь — это упакует весь проект вместе с `uploads/`.

## Шаг 3. Отчитайся
Кратко: какие записи changelog вошли в область хендоффа, какие экраны реализуются, что вне области.
Напомни флоу: распаковать zip в репо → отдать дев-агенту папку + `HANDOFF.md`.

## Бэкап в git
Автокоммита нет. Нужен репозиторий — используй GitHub-интеграцию (`connect_github`, затем `github_*`);
если инструменты недоступны — вызови `connect_github` и заверши ход. Иначе — ручной путь (zip).
Спроси, какой путь нужен; не предполагай.

## Чего не делать
- Не выгружать `uploads/` — это рабочие исходники агента.
- Не паковать пустым путём — затянет `uploads/`; всегда пакуем staging-папку.
- Не паковать подмножество макетов — в zip весь проект кроме `uploads/`; адресность задаёт `HANDOFF.md`.
- Не хардкодить в инструкции цвета/размеры — только токены `--*`.
- Не предполагать способ бэкапа (git vs zip) — спросить.
