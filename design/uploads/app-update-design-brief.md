# ТЗ дизайнеру: «Обновление приложения»

Дата: 2026-11-14 · Приложение: новая версия «Специалист» (Android, iOS, desktop Windows/macOS)

Макет экрана обновления уже есть, но только для desktop и без каналов: `design/features/app-update/`
(`AppUpdateScreen.jsx`, `AppUpdate.html`, состояния available / checking / downloading / downloaded / uptodate / error).
Нужно его **доработать**:
1. добавить на desktop выбор **канала обновлений** (например, «Релиз» / «Бета»);
2. уточнить состояния под реальную установку на Windows и macOS;
3. сделать **мобильный вариант** (Android, iOS): описание новой версии и кнопка перехода в магазин приложений;
4. дать вход в обновление на мобильном главном экране.

Макеты — на нашем UI-ките (Material 3, компоненты Cmp*): телефон и широкое окно (планшет/desktop), светлая и
тёмная темы. Перечень и приоритеты — в п. 7.

Связанные документы:
- ТЗ программисту — `app-update.md`;
- главный экран — `design/features/home/` (раздел «Обновление приложения (desktop)»: строка «Проверить обновления»
  в боковом меню, блок «Доступна новая версия» внизу бокового бара);
- иконки старого desktop — `design/res/icons/legacy/rhm_update.svg`, `token_update.svg` (смысл, не вид).

## 1. Контекст

**Кто пользуется.** Монтажник/сотрудник сервиса. Задача — держать приложение свежим, не думая об этом: увидеть, что
вышла новая версия, прочитать, что в ней нового, и обновиться в пару нажатий. Небольшая часть пользователей
(тестировщики, «продвинутые» монтажники) хочет получать **бета-версии** раньше остальных.

**Как было (старый desktop).** Экран «Обновление приложения»: текущая версия; если есть новая — номер, дата,
описание, кнопки «Обновить» и «Скачать» (сохранить установщик в файл). Ниже — «Другие версии»: список других
каналов, у каждого кнопка «Перейти». Во время загрузки — спиннер и «Отмена», затем «Обновление загружено, приложение
будет перезапущено». При старте — всплывающее уведомление «Доступна новая версия» с кнопкой «Обновить». Переносим
смысл, не вид.

**Каналы.** Это списки сборок на сервере. Названия задаёт администратор («Релиз», «Бета», «Тест»…) — приложение
показывает их как есть, длина произвольная. Пользователю доступны 1…несколько каналов; один из них выбран (по
умолчанию — общий «релизный»). Выбор канала хранится на устройстве.

**Какие данные приходят о новой версии:**

| Поле | Пример | Примечание |
|---|---|---|
| Версия | 2.1.0 | всегда |
| Дата публикации | 12.11.2026 | всегда |
| Описание «Что нового» | многострочный текст | может быть пустым или длинным (20+ строк), простой текст, переносы строк, маркеры «-» |
| Размер файла | 180 МБ | **может быть неизвестен** до начала загрузки |

Текущая версия приложения: `2.1.0 (210)` + версия базы настроек (сейчас показывается как `-s1234`).

## 2. Экран «Обновление приложения» — desktop (Windows, macOS)

Заголовок «Обновление приложения», «Назад». Открывается из бокового меню («Проверить обновления»), из блока
«Доступна новая версия» внизу бокового бара, из уведомления при старте и из значка «Нужно обновить приложение» в
топбаре главного (база настроек требует более новую версию приложения).

### 2.1. Шапка
- Текущая версия (и версия базы — мелко, вторичным текстом).
- Текущий канал — например, «Канал: Бета» рядом с версией или в отдельной секции (п. 2.3).

### 2.2. Состояния
1. **Проверка** — индикатор; повторное открытие экрана тоже проверяет заново.
2. **Доступна новая версия** — текущая → новая версия (пилюли из текущего макета), дата публикации, «Что нового»
   (длинный текст — сворачивать после N строк с «Показать полностью» или скролл, на ваше усмотрение).
   Кнопки:
   - **«Обновить»** (основная) — скачать и установить;
   - **«Скачать файл»** (вторичная, ссылка или outlined) — сохранить установщик в выбранную папку, если
     автоматическая установка не сработала;
   - «Позже» — если экран открыт из уведомления/баннера.
   В текущем макете кнопка «Скачать .dmg» — **убрать расширение**: на Windows это `.exe`.
3. **Загрузка** — прогресс + «Отменить». Размер может быть неизвестен: нужны **оба** варианта — определённый
   (`43 из 180 МБ · 24 %`) и неопределённый (бегущий индикатор + `43 МБ загружено`). Сейчас SDK размер не отдаёт —
   в приложении неопределённый вариант. Уход с экрана сейчас отменяет загрузку; если нужна загрузка в фоне с
   прогрессом на главном (блок внизу бокового бара) — нарисуйте, сделаем отдельно.
4. **Готово к установке** — «Обновление загружено». Основная кнопка «Установить и перезапустить».
   Под ней пояснение: «Приложение закроется, установит обновление и откроется снова».
   Отличия платформ (одним вспомогательным текстом, не разными экранами):
   - Windows — откроется окно установщика, в нём нужно нажать «Далее»/«Установить»;
   - macOS — установка без окон, через несколько секунд приложение откроется само.
5. **Установка запущена** — короткое состояние перед закрытием (1–3 с): «Устанавливаем обновление…»
   Если в этот момент идёт работа с блоком (подключение по BLE/USB, запись настроек, прошивка), сначала нужно
   **предупреждение**: «Идёт работа с блоком. Обновиться сейчас? Соединение будет прервано» — «Обновить» /
   «Отмена». Нарисуйте диалог.
6. **Установлена последняя версия** — «У вас последняя версия» + текущий канал. Кнопка «Проверить снова».
7. **Ошибки** (нейтральный тон, кроме сбоя загрузки):
   - нет сети — «Нет подключения к интернету» + «Повторить»;
   - ошибка сервера — общий текст + «Повторить»;
   - в канале нет сборок — «В канале «Бета» пока нет версий»;
   - загрузка прервалась — «Не удалось загрузить обновление» + «Повторить» (начинает заново);
   - файл не подходит — «Файл обновления не подходит для этого компьютера. Скачайте установщик с сайта» + «Скачать
     файл» / ссылка.

### 2.3. Канал обновлений (только desktop)
Секция «Канал обновлений» ниже основного блока:
- список доступных каналов с выбором одного (радио-строки или сегменты — при 2–3 каналах; предусмотрите 5+ и
  длинные названия);
- под списком подсказка, что такое бета: «Бета — новые функции раньше всех, но возможны ошибки»;
- **секции нет**, если доступен только один канал;
- смена канала сразу запускает проверку (состояние «Проверка» в основном блоке);
- **отката нет**: если в выбранном канале версия старше установленной (ушли с «Беты» 2.2.0 на «Релиз» 2.1.0) —
  приложение остаётся на текущей. Нужен понятный текст в состоянии «Последняя версия», например:
  «В канале «Релиз» сейчас 2.1.0 — она старше установленной. Обновление придёт, когда в канале выйдет версия
  новее». Нарисуйте этот вариант отдельно.
- Подтверждения при переходе на бету не нужно (на ваше усмотрение — если считаете важным, предложите).

### 2.4. Главный экран (desktop)
Уже есть в `home/`: «Проверить обновления» в меню и блок «Доступна новая версия». Добавить:
- блок во время загрузки (прогресс) и «Готово к установке» (кнопка «Установить»);
- уведомление при старте (snackbar/toast) «Доступна версия 2.1.0» + «Обновить» — один раз за запуск.

## 3. Мобильный вариант (Android, iOS)

На телефоне приложение обновляется только через магазин. Каналов **нет**. Экран тот же, «Обновление приложения»:
1. **Проверка**;
2. **Доступна новая версия** — текущая → новая, дата, «Что нового», основная кнопка **«Открыть в Google Play»**
   (Android) / **«Открыть в App Store»** (iOS); «Позже». Кнопки «Скачать файл» и прогресса нет;
3. **Последняя версия**;
4. **Нет сети**, **ошибка сервера** — как на desktop.

Важно: версия в магазине может появиться позже, чем на нашем сервере (модерация). Дайте мягкую подпись у кнопки:
«Если обновление ещё не появилось в магазине, попробуйте позже».

### 3.1. Вход на мобильном главном
Сейчас на телефоне/планшете UI обновления нет совсем (`appUpdate=null` в `home/`). Предложите место:
- плашка/карточка «Доступна новая версия 2.1.0» на главном (закрываемая — крестик, вернётся при следующей новой
  версии), **и/или**
- пункт «Обновление приложения» с точкой-индикатором там, где на мобильном лежат настройки/«О приложении».
Плюс значок «Нужно обновить приложение» в топбаре (уже есть) ведёт на этот экран.

## 4. Адаптивность
- Телефон — одна колонка.
- Широкое окно (≥ 840 dp, desktop) — контент по центру с максимальной шириной (`CmpAdaptiveBox`), «Что нового» и
  «Канал обновлений» — одной колонкой ниже версии или двумя колонками (основной блок | каналы) — на ваше усмотрение.
- Планшет — как телефон с большими отступами (каналов нет).

## 5. Тексты
Черновики — в п. 2–3 и в старом desktop (`APP_UPDATE_*`, `UPDATE_*`: «Загрузка обновления», «Обновление загружено.
Приложение будет автоматически обновлено и перезапущено», «Другие версии», «Перейти»). «Другие версии» — неточное
название (это каналы), заменить. Финальные формулировки — на ваше усмотрение, RU и EN.

## 6. Иконки
Обновление (меню, блок, пустое/«последняя версия»), загрузка, магазин (Google Play / App Store — системные знаки
не рисуем, достаточно общей иконки «открыть во внешнем»), предупреждение «идёт работа с блоком», ошибка файла.
