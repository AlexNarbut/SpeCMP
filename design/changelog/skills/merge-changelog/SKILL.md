# Слияние черновиков changelog в финальную запись

Цель: по завершении работы над связанным функционалом схлопнуть накопленные **черновики-фрагменты**
из бакета-поддиректории (`changelog/current/` или именованного `changelog/<слаг-фичи>/`, по одному
фрагменту на чат) в одну **финальную запись** `changelog/<дата>-<экраны>.md` в корне `changelog/` и
удалить слитый бакет.

Контракт проекта (см. `changelog/README.md`):
- Финальные записи `<дата>-<экраны>.md` лежат в **корне** `changelog/` — это каноническая история,
  её читают скиллы `import-by-changelog` и `export-handoff`.
- Бакеты-поддиректории (`current/` и `<слаг-фичи>/`) — **временные** черновики с фиксированными
  именами без даты; копятся по чатам и удаляются при слиянии.

**Запускай только по явной просьбе пользователя.** Сам слияние не инициируй.

---

## 0. Выбери бакет

1. `list_files("changelog")` — раздели на:
   - финальные записи `<дата>-<экраны>.md` и `README.md` в корне (их **не трогаем**, кроме записи нового файла);
   - бакеты-поддиректории (`current/`, `<слаг-фичи>/`) — это черновики.
2. Определи, **какой бакет** сливать:
   - пользователь назвал бакет/фичу явно → берём его;
   - бакет ровно один → берём его;
   - бакетов несколько и не указано какой → **спроси** пользователя, какой сливать.
3. Прочитай все `*.md` внутри выбранного бакета — это фрагменты к слиянию (`fragments`).
4. Если бакет пуст или фрагментов нет — сообщи, что сливать нечего, и заверши.

> Сливаем **один** бакет за вызов (он = одна связанная фича). Другие бакеты не трогаем.

---

## 1. Слей фрагменты в одну запись

Собери поля из всех фрагментов бакета:

- **Заголовок** — `# <дата> — <краткое название задачи>`. Сформулируй название, обобщающее работу.
- **Дата** — дата **завершения** (обычно = сегодня). Если работа шла несколько дней — можешь
  упомянуть период первой строкой тела, но в имени файла — одна дата (завершения).
- **Экраны:** — объединение значений `Экраны:` из всех фрагментов, без дублей, в нижнем регистре.
- **Файлы:** — объединение секций `Файлы:` всех фрагментов, дедуп по пути. На выходе — **списком через `-`**.
- **## Что изменилось** — объедини буллеты, убери дубли, сгруппируй по смыслу/экрану.
- **## Зачем** — объедини обоснования.
- **## Заметки** — объедини известные ограничения и «осталось на потом», дедуп.

Держи итог по структуре из `changelog/README.md` — ровно те же секции и порядок.

---

## 2. Запиши финальную запись

1. Имя файла: `changelog/<дата>-<экраны>.md`, где `<экраны>` — объединённый список через дефис в нижнем регистре.
2. Проверь коллизию: если такой файл уже есть в корне `changelog/` — добавь суффикс `-2`, `-3`.
   Не перезаписывай существующую финальную запись.
3. Запиши файл (`write_file`).

---

## 3. Удали слитый бакет

После успешной записи финальной записи удали **слитый** бакет целиком:
`delete_file({ paths: ['changelog/<бакет>/'] })`.

- Удаляй **только** слитый бакет. Другие бакеты, корневые финальные записи и `README.md` не трогай.
- Если сливали `current/` — он будет заново создан следующим чатом по мере надобности.

---

## 4. Отчитайся
Кратко: какой бакет слит и в какую финальную запись, сколько фрагментов вошло, что осталось вне слияния.

## Кратко (happy path)
1. Выбрать бакет (если несколько и не указано — спросить).
2. Собрать фрагменты бакета.
3. Объединить поля, дата = дата завершения.
4. Записать `changelog/<дата>-<экраны>.md` (проверить коллизию).
5. Удалить слитый бакет.
6. Отчитаться.

## Чего не делать
- Не запускать слияние без явной просьбы пользователя.
- Не сливать несколько бакетов за один вызов — один бакет = одна фича.
- Не перезаписывать существующие финальные записи и `README.md`.
- Не терять пути из секций `Файлы:` — они манифест для `import-by-changelog` и `export-handoff`.
