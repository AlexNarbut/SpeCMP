## Что изменилось

### Устройства системы
- Группы по типам в порядке каталога (16 типов); показываются только непустые.
- Опрос: в шапке «Опрос блока… N из 16» + полоса; найденные группы дописываются снизу (порядок опроса = порядок каталога, список не прыгает), ниже — скелетон и «Опрашиваем: <тип>…». После прохода — сводка.
- Сводка: «N требуют внимания · X устройств · Y на связи» → «Показать» прокручивает к проблемному и подсвечивает строку. Тон сводки: ошибка при «Нет связи», предупреждение при «Вне зоны»/слабом сигнале/низком заряде.
- Строка устройства (вариант A): иконка, заголовок + адрес, статус справа; индикаторы и показатели второй строкой. Проблемные строки тонируются. Варианты B (карточка) и C (статус крупно) отклонены.
- Сигнал: 4 полоски + «−67 dBm», классы ≥−60 / −61…−75 / −76…−85 / <−85; слабый — предупреждающим тоном, очень слабый — ошибкой. Батарея: 4 уровня + «Низкий заряд», напряжение «2,95 В».
- Подробнее: лист (телефон) / панель справа (≥760) — тип, номер, адрес, статус, сигнал с классом, батарея с %, показатели типа; «Обновляется каждые 2 с».
- «Обновить» в «Подробнее» — у всех типов, кроме TPMS (не на связи — недоступно с пояснением). Подтверждение «Обновить Метка 2?» → «Переводим в режим прошивки…» → «Закрываем сессию…» → экран поиска устройств (`device-select`), где устройство выбирается для прошивки. Ошибка — «Повторить».
- «Поморгать» в «Подробнее» — у меток и датчиков двери, рядом с «Обновить»: устройство моргает светодиодом (кнопка «Моргает…» 3 с + снэкбар).
- Пусто: «К блоку не приживлено ни одного устройства» + «Приживить устройство» (только если у блока динамическая таблица). Переход в приживление — из шапки экрана, по тому же условию.
- Демо-панель: тема, экран, «Фаза 1 / Фаза 2», «Блок с динамической таблицей / Без приживления», «Устройство отвечает / Не отвечает», пресеты U1–U7.
- Шапка «Базовый блок / BLE-модуль» (модель, прошивка, версия BLE) — всегда над сводкой, без кнопок.

### Приживление устройств
- Слоты группами: Метки, Реле, Датчики, Датчики шин (TPMS); «Занято N из M», счётчик на группу.
- Строка слота: иконка (свободный — пунктир, приглушённо), статус, напряжение / адрес PIR; у свободного — кнопка «Приживить» прямо в строке.
- Действия (лист / панель справа): свободный — «Приживить», «Инструкция»; занятый — «Инструкция», «Обновить» (метка «Опционально»), «Удалить».
- TPMS: ввод адреса (8 hex, проверка формата, ошибка), место под «Сканировать QR» (метка «Позже»).
- Режим приживления — 2 варианта на телефоне: закреплённая карточка над списком (инструкция раскрывается) или отдельный шаг (инструкция видна сразу). На широком окне — панель справа, инструкция всегда видна. Отсчёт 2:00 кольцом, предупреждение из ТЗ, «Отмена»; слот в списке — «Ожидает устройство…» с пульсом.
- Итог: успех («Радиореле 2 приживлено», слот вспыхивает «На связи», «Готово»); не удалось (время вышло: «Повторить», «Инструкция», «Закрыть»).
- Подзаголовок экрана — модель блока и канал связи (Bluetooth / USB).
- Удаление: «Удалить Метка 2?» → «Удаляется…» в строке → снэкбар «Устройство удалено».
- D1 загрузка (вход в программирование → чтение), D3 все свободны, D10 PIN / PIN заблокирован, D11 «Снимите с охраны и выключите зажигание» + «Повторить», D12 ошибка чтения, D13 «Команда не поддерживается».

### Иконки и схемы
- Иконки типов — легаси (по решению), перекрашены в currentColor. Каждая отцентрована и вписана в квадрат по реальным границам рисунка (отступ 4 %). Все элементы переведены в контур одной толщины (1,8 px при любом размере, скруглённые концы), невидимые служебные контуры удалены. «Нет связи» — бейдж, свободный слот — пунктир. Вариантов `_disconnect` не используем (кроме замка капота — единственный исходник).
- Схемы приживления: линия currentColor, светлые заливки → surface, одиночный красный акцент (nav_10, vs) → primary; цвета проводов в ps_331, bt_01, rhm_03 сохранены.

### Плитки и доступность
- «Устройства системы» — только Bluetooth. «Приживление устройств» — Bluetooth и USB, только у блоков с динамической таблицей (`dynamic` в профиле). В сетке это проверяется фильтром (`bleOnly`, `needsDynamic`).
- Переходы между экранами: из «Устройств» в «Приживление» — только если у блока динамическая таблица; из «Приживления» в «Устройства» — только по Bluetooth (по USB кнопки нет). В демо — переключатели «Блок с динамической таблицей / Без приживления» и «Bluetooth / USB».
- Плитка «Устройства системы» / «Состояние меток, реле и датчиков».
- «Доп. устройства» переименована в «Приживление устройств», открывает экран слотов.

### Раскладной телефон
- Страница `PeripheralDevicesFoldable.html` (`psGo('peripheral-devices-foldable')`), три положения; ориентир — Galaxy Z Fold.
- Сложен, внешний экран 344×882 — Compact: одна колонка, «Подробно», действия и инструкции — нижние листы.
- Разложен 690×829 — как desktop: слева список, справа «Подробно» с командами («Поморгать», «Обновить») / действия слота и режим приживления с инструкцией. Граница колонок — по сгибу (панель = половина ширины).
- В узкой левой половине: строка слота без иконки на «Приживить», шапка блока — в столбик.
- Разложен горизонтально 829×690 — штатные две колонки (≥760), сгиб горизонтальный.
- Экраны получили параметры `splitAt` (порог двух колонок, по умолчанию 760) и `panelWidth` (ширина правой панели) — для раскладных окон.
- Рамка устройства в макетах (раскладной и планшет) больше не масштабируется дважды: обрамление ровное, сгиб по центру, камера в углу.

## Решения по ходу работы
- Строка устройства — только вариант A; B и C убраны из макетов и листа состояний.
- Шапка «Базовый блок / BLE-модуль» — обязательна, без кнопки «Обновить прошивку».
- «Обновить» (режим прошивки) — основная команда в «Подробнее» для всех типов, кроме TPMS; после подтверждения сессия закрывается и открывается поиск устройств.
- «Поморгать» — основная команда для меток и датчиков двери (не фаза 2).
- Иконки типов отцентрованы, отмасштабированы и приведены к одной толщине линии.
- Раскладной телефон в разложенном виде — двухколоночный, как desktop (не одна колонка).

## Заметки
- В ДС нет роли warning — введён локальный `--pd-warn*` (светлая/тёмная); предлагаю добавить токен в дизайн-систему.
- Текст инструкции есть только для BTR-101; остальные типы — схема + пометка до выгрузки `text_device_manual_pairing_*`.
- Нет легаси-иконок: часы отдельно, браслет, иммобилайзер, NFC, ALT-420, телефон, неизвестное — временно Material-символы.
- Соответствие схем типам (ps_331/332, control_device, d_030) — предположение, сверить.
- Формат адреса TPMS (8 hex) — предположение, сверить с ТЗ программисту.
- Режим приживления (карточка/шаг) — выбрать один.
