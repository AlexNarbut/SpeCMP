# Changelog макетов

Эта директория хранит историю изменений макетов проекта Pandora Spec.

История ведётся в **два этапа**: каждый чат пишет свой черновик-фрагмент в бакет-поддиректорию, а по
завершении связанного функционала фрагменты бакета сливаются в одну финальную запись (скилл
`skills/merge-changelog/`).

## Структура директории

```
changelog/
  README.md                         этот файл
  <дата>-<экраны>.md                ФИНАЛЬНЫЕ записи (история) — лежат в корне changelog/
  current/                          СТАНДАРТНЫЙ бакет-черновик (по умолчанию)
    <слаг-экранов>.md               черновик-фрагмент одного чата
    <слаг-экранов>-2.md             ещё фрагмент (при коллизии имён внутри бакета)
  <слаг-фичи>/                      ОТДЕЛЬНЫЙ бакет под конкретную фичу (опционально)
    <слаг-экранов>.md               фрагменты этой фичи, копятся через несколько чатов/дней
```

- **Финальные записи** (`<дата>-<экраны>.md` в корне) — каноническая, неизменяемая история. Их читают
  скиллы `import-by-changelog` и `export-handoff`.
- **Бакеты-поддиректории** (`current/` и именованные `<слаг-фичи>/`) — рабочие черновики. Имена
  **фиксированы и без даты**. Бакет **удаляется при слиянии**; скиллы истории бакеты игнорируют.

## Этап 1. Черновик-фрагмент (в каждом новом чате)

Как только в чате начинается работа над функционалом:
- **Спроси пользователя, в какой бакет писать**: стандартный `changelog/current/` или отдельный
  `changelog/<слаг-фичи>/`. По умолчанию — `current`.
- Убедись, что бакет-поддиректория существует, иначе создай.
- Создай в ней **новый** фрагмент `<слаг-экранов>.md` и заполняй по ходу работы.
- В пределах одного чата — **один** фрагмент: новый чат → новый файл, тот же чат → правишь этот же файл.
- Коллизия имени внутри бакета → суффикс `-2`, `-3`.

## Этап 2. Слияние (по завершении фичи, явно)

Пользователь явно вызывает `skills/merge-changelog/` (при нескольких бакетах — указывает, какой
сливать). Скилл собирает все фрагменты бакета, сливает их в одну финальную запись `<дата>-<экраны>.md`
в корне `changelog/` (дата = дата завершения) и удаляет слитый бакет.

## Формат имён финальных записей

```
<дата>-<список_изменённых_экранов>.md
```

- **дата** — `ГГГГ-ММ-ДД` (дата завершения / слияния, например `2026-06-30`).
- **список_изменённых_экранов** — экраны через дефис, в нижнем регистре (например `calculator`).

Примеры:
- `2026-06-30-calculator.md`
- `2026-07-02-settings.md`

При коллизии имён добавляйте суффикс `-2`, `-3`.

## Структура записи (и фрагмента, и финальной)

```md
# <дата> — <краткое название задачи>

**Экраны:** calculator
**Файлы:** features/calculator/Calculator.jsx, features/calculator/Calculator.html

## Что изменилось
- Пункт 1
- Пункт 2

## Зачем
Короткое обоснование / контекст задачи.

## Заметки
Известные ограничения, что осталось на потом.
```
