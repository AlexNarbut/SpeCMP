# UI-тестирование

Ты — оркестратор. Общаешься с пользователем и раздаёшь работу субагентам; сам экраны не исследуешь и
кейсы не прогоняешь — это дорого на основной модели.

| Субагент | Роль | Промпт |
|---|---|---|
| `ui-test-planner` | `plan.md` + `flows/<ID>.yaml` | `.agents/skills/ui-test/roles/planner.md` |
| `ui-test-runner` | прогон одного этапа на одной платформе → `run.md` | `.agents/skills/ui-test/roles/runner.md` |
| `ui-test-reviewer` | `review.md` + `coder-task.md` | `.agents/skills/ui-test/roles/reviewer.md` |

**Запуск роли.** Запусти субагента с этим именем (Claude Code, Codex, Kimi Code, Gemini CLI — все
поддерживают субагентов проекта). Если субагенты недоступны — выполни роль сам: прочитай
`.agents/skills/ui-test/roles/<role>.md` и действуй строго по нему, затем вернись к этому сценарию.

**Вопросы пользователю** — через инструмент вопросов с вариантами, если он есть; иначе коротким текстом
со списком вариантов и ожиданием ответа.

Все пути — от корня репозитория. Файлы скилла: `.agents/skills/ui-test/` (шаблоны, роли, скрипты, креды).
Папка теста: `.ai-qa/<slug>/`, `slug` = `<feature>-<YYYY-MM-DD>`. Состав папки, шаблоны и правила
оформления — `.agents/skills/ui-test/templates/RULES.md` (субагенты читают его сами; правишь документы
руками — тоже по нему). Скрипт: `U=.agents/skills/ui-test/scripts/ui.sh` (`$U help`).

## Режимы

- `ui-test <описание | путь к задаче>` — полный цикл, шаги 0–6.
- `ui-test rerun <папка теста>` — повторная проверка после доработок: шаги 0–2, затем runner в режиме
  `rerun` по кейсам из приёмки `coder-task.md` (или всем ❌/⚠️ в `run.md`), затем шаг 5.
- `ui-test continue <папка теста>` — продолжить прерванный прогон с первого `[ ]` в `run.md`: шаги 0–2, 4, 5.

## 0. Платформа

Если не указано во входе — спроси платформы (можно несколько): Android / iOS / Desktop.

## 1. Окружение

`$U doctor <platform>` для каждой выбранной платформы. Любой ❌ — покажи пользователю пункт и команду из
вывода, предложи выполнить её (установка через brew, запуск эмулятора/симулятора); для кредов — попроси
заполнить `.agents/skills/ui-test/credentials.properties` по примеру `credentials.properties.example`.
Не продолжай, пока `doctor` не вернёт `OK`. Нет нужного устройства — эмулятор/симулятор можно запустить самому
(`emulator -avd <name>` в фоне; `xcrun simctl boot <udid> && open -a Simulator`), спросив пользователя.

## 2. Сборка

Для Android и iOS: `$U use <platform>`, затем `$U build` и `$U install`.
Для desktop: `$U use desktop`, `$U build` (компиляция), затем `$U launch` — приложение стартует через Gradle в
фоне и остаётся запущенным на весь прогон (уже запущенное — переиспользуется).
Сборка упала — покажи ошибку пользователю и остановись: чинить код приложения в этом скилле нельзя.
Если пользователь хочет тестировать уже установленную сборку — пропусти `build`/`install`
(для нестандартного id: `use … --app-id <id>`).

## 3. План

Запусти `ui-test-planner` с: исходным входом (дословно), папкой теста, платформами, билдом
(`git rev-parse --short HEAD`, ветка). Покажи пользователю ответ планировщика и путь к `plan.md`. Спроси:
апрув / правки (добавить, убрать, поменять приоритет). Небольшие правки — внеси сам; крупные — перезапусти planner.
**Без апрува плана прогон не начинать.**

## 4. Прогон

Для каждого этапа `plan.md`, для каждой выбранной платформы по порядку Android → iOS → Desktop:
1. `$U use <platform>` (переключает устройство для runner'а).
2. Запусти `ui-test-runner`: папка теста, номер этапа, платформа. Один запуск = один этап (3–4 кейса).
   Этапы на разных платформах **не** запускай параллельно — runner'ы делят `run.md` и состояние ui.sh.
3. Покажи пользователю краткий итог этапа (таблица runner'а) и переходи к следующему. Останавливайся и
   спрашивай, только если: этап целиком ⏭/❌ из-за окружения (не загружается приложение, нет сети, аккаунт
   заблокирован, нет BLE-устройства) или runner сообщил, что предусловия невыполнимы.

## 5. Ревью

Все кейсы ✅ и в `run.md` пусты «Отклонения» и «Попутно» — reviewer не запускай: напиши `review.md` сам
(только «Вердикт: готово · ✅ N · ❌ 0 · ⚠️ 0 · ⏭ 0»), `coder-task.md` не создаётся.
Иначе запусти `ui-test-reviewer` с папкой теста. Покажи пользователю вердикт, блокеры, путь к `review.md`.
Если создан `coder-task.md` — предложи передать его агенту-кодеру как файл задачи, после доработки —
`ui-test rerun <папка теста>`. Пункты «Инструмент» из `run.md` покажи отдельно: это доработки `ui.sh`.

## 6. Уборка

`$U stop` на всех платформах (на desktop это закрывает приложение). На Android ещё `$U net on` — на случай,
если runner не вернул сеть после офлайн-кейса. Эмулятор/симулятор не выключай.

## Правила

- Креды не выводи в чат и не пиши в документы — только ключи (`<QA_EMAIL>`).
- Код приложения не меняешь ни ты, ни субагенты.
- Папка теста — единственный источник состояния: всё важное — в `plan.md` / `run.md` / `review.md`, не в чате.
