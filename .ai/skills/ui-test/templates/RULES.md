# Правила оформления QA-документов

Папка теста: `.ai-qa/<slug>/`, `slug` = `<feature>-<YYYY-MM-DD>` (латиница, kebab-case).

| Файл | Пишет | Шаблон |
|---|---|---|
| `plan.md` | ui-test-planner | `templates/plan.md` |
| `run.md` | ui-test-runner | `templates/run.md` |
| `review.md` | ui-test-reviewer | `templates/review.md` |
| `coder-task.md` | ui-test-reviewer | `templates/coder-task.md` — только если есть что дорабатывать |
| `flows/<ID>.yaml` | planner пишет, runner правит | Maestro-флоу кейса с проверкой после каждого шага |
| `shots/`, `logs/` | ui-test-runner | `<ID>-<platform>[-<суть>].png`, `<ID>-<platform>.log`; platform — `android` / `ios` / `desktop` |
| `flows/out/` | ui.sh | скриншоты флоу; `debug-*` — только для упавших |

## Стиль

- Заголовки, порядок разделов и колонки таблиц — строго как в шаблоне. Пустой раздел удаляется
  (кроме таблиц статусов и разделов `run.md` — их заполняет runner по ходу прогона).
- Только факты. Без вступлений, пересказа шагов, оценок «корректно», «успешно», «как и ожидалось».
- Таблица, если записей больше одной. Ячейка таблицы — до 10 слов.
- Абзац — до 2 строк. Если нужно больше — список или кодовый блок.
- ✅ не описывается вообще: статус в таблице и всё.
- Тексты UI — в кавычках «Как на экране», селекторы — `#testTag`, файлы — `моноширинным`.
- Пути — относительно папки теста: `shots/TC-02-android.png`, а не полный путь.
- Скриншот прикладывается редко: к ❌ / ⚠️ и к визуальным проверкам (вёрстка, цвет, картинка).
  В остальных случаях достаточно описания по `tree`.
- Лог — выдержка 5–15 строк в кодовом блоке; полный лог — в `logs/`.

## Данные

- Значения кредов никогда не пишутся — только ключ: `<QA_EMAIL>`, в т.ч. когда значение видно на экране
  («For <QA_EMAIL>»).
- Проблемы инструмента (ui.sh, Maestro, эмулятор) — только в `run.md` → «Инструмент», не в ревью приложения.
