# core/push

- Область: платформенная часть push-уведомлений без SDK и аккаунта (задача — `.claude/tasks/push-notifications.md`).
- `PushType` (коды `type_id` сервера: 1 NOTIFICATION, 4 WARNING, 5 CHAT; 2/3/6 — новости, видео, статьи — не показываем), `PushPayload.parse(data, notificationTitle, notificationBody)` (`data` перекрывает `notification`-блок; `null` — тип не показываем или нет текста), `PushPayload.target` / `targetOf(data)` → `PushTarget` (`Chat`, `Url` — только http(s) у NOTIFICATION, `App`).
- `PushOpenRequests` — `object` процесса, а не Koin: Android-активити кладёт тап в `onCreate`, а Koin поднимается внутри композиции (`App()`). `offer(data)` (запуск не из уведомления игнорируется, последний тап заменяет прежний), `pending: StateFlow`, `consume(target)` (CAS), `open(target)` (тап без данных push — desktop), `clear()` на logout. Потребитель — только `PushOpenEffect` в `AuthedNavGraph` (`composeApp`).
- `PushTokenSource` (`token(): Response<String?>`, `null` — у платформы нет push) — он же `AuthCloseable`: при выходе из аккаунта удаляет токен и чистит `PushOpenRequests`. `di/pushPlatformModule()` (expect): Android — пустой (токен даёт модуль магазина: `core/push-fcm` — `fcmPushModule()`, `core/push-hms` — `hmsPushModule()`; подключает флейвор `androidApp` через `App(storeModules)`), iOS и desktop — `MessagingClientPushTokenSource` над `PushMessagingClient` (Firebase из Swift; клиента нет — токен `null`, как без push): iOS — `IosPush.client`, desktop — `DesktopPush.client` (только macOS `.app` с профилем). `ApsUserInfo` — разбор `userInfo` APNs (данные — ключи верхнего уровня без `aps`, `hasAlert`), общий для iOS и macOS.
- Важно для Android: когда push-сервис будит процесс в фоне, Koin и SDK не подняты (стартуют в композиции) — приём и показ push не должны от них зависеть; отправка токена на сервер — только из живого приложения (`feature/push`).
- Android без SDK магазинов: общая база вендорных модулей — `AndroidPushTokenSource` (каналы перед токеном, logout: `PushOpenRequests.clear()`, `cancelAll`, удаление токена; наследник даёт `requestToken`/`deleteToken`) и `AndroidPushReceiver.show(context, data, title, body, messageKey)` (suspend, не на main) для сервиса приёма (`PushPayload.parse` → `AndroidPushNotifier`; без разрешения не показывает). Каналы `PushChannel` с id старого приложения (`FcmNotificationType_NOTIFICATION` / `_ATTENTION` / `_SUPPORT`) и именами из `Strings` (`push.xml`, язык — `prepareAppLocale()`), иконки — `res/drawable/ic_push_*`. Чат — фиксированный id (новое сообщение заменяет прежнее). `image_url` (https) — `BigPictureStyle`. Манифест модуля — только `POST_NOTIFICATIONS`.
- Тап: `PendingIntent` на launcher-активити с `type_id`/`action_url` в extras; `AppActivity` зовёт `PushOpenRequests.offer(intent)` в `onCreate` (если `savedInstanceState == null`) и `onNewIntent`; открытие из «Недавних» — не тап. Push с `notification`-блоком в фоне показывает сам push-сервис (канал и иконка — в манифесте вендорного модуля), extras те же.
- Firebase на Android — только `core/push-fcm` (флейвор `google`), HMS — только `core/push-hms` (флейвор `huawei`): `google-services.json` — `androidApp/src/google/`, плагин `com.google.gms.google-services` — в `androidApp` (проект `pandora-specialist-6663f`, пакет `ru.alarmtrade.pandoraspecialist`). В `core/push` SDK push-сервисов нет.
- iOS: Firebase Messaging — только в Swift (SPM `firebase-ios-sdk`, `iosApp/AppDelegate.swift`), у Kotlin биндингов нет. Мост — `IosMessagingClient` (получить/удалить FCM-токен колбэками) и `IosPush` (`object`, до Koin): `install(client)`, `onNotificationOpened(userInfo)` → `PushOpenRequests`, `onRemoteMessage(userInfo)` — push без `aps.alert` показывает `IosPushNotifier` (`UNUserNotificationCenter`, чат — один идентификатор), с alert показала система. Swift видит их через `composeApp/iosMain` `PushBridge` / `IosFirebaseMessaging` (типы `core/push` в framework — с префиксом модуля). Logout — `removeAllDeliveredNotifications` + `deleteToken`.
- macOS: APNs + Firebase Messaging в нативной библиотеке `desktopApp/native/macos` (Swift), мост — `composeApp/jvmMain` `MacNativeBridge` → `DesktopPush` (`object`, до Koin): `install(DesktopMessagingClient)`, `onNotificationOpened(userInfo)` → `PushOpenRequests`, `shouldPresent(userInfo)` — push с alert при открытом приложении (чат и скрытые типы — нет: о чате сообщает `DesktopChatNotifier` по живому соединению), `onRemoteMessage(userInfo)` — push без alert показывает клиент (чат — нет). Закрытое приложение: alert-push показывает система, data-push не доходит. Windows/Linux — push нет.
