# core/speech

- Область: озвучка фраз (нейросетевой голос Piper для русского на Android/desktop, иначе голос системы) и флаг режима «Руки заняты» (задача — `.claude/tasks/hands-free.md`). UI (кнопка, подсказка «нет голоса», строки) и решения «что говорить» — не здесь: фразы строят VM экранов, кнопка — `feature/device/presentation-core`.
- `Speaker` (Koin `single`, `di/speechModule`): `speak(text, mode)` — `SpeechMode.FLUSH` обрывает текущую фразу и очищает очередь, `QUEUE` ставит в очередь; фраза, совпадающая с последней поставленной, игнорируется (повторная эмиссия того же состояния), пустая — тоже; `stop()` — замолчать, очистить очередь и забыть последнюю фразу (после возврата на экран шаг прозвучит снова); `availability: StateFlow<SpeechAvailability>` — `Ready` / `NoVoice(canInstall)` / `Unsupported`; `speaking: StateFlow<Boolean>` — очередь не пуста (звучит фраза или ждёт следующая; гаснет, когда очередь опустела или после `stop()`) — для состояния кнопки «говорит»; `openVoiceInstall()` — Android `ACTION_INSTALL_TTS_DATA`, на остальных no-op.
- Правила очереди, неповтора и остановки — только в общем `QueuedSpeaker` (поколения очереди + `collectLatest`: FLUSH/stop отменяют корутину фразы). Платформы — тонкий `SpeechEngine`: `prepare()`, `speak(text)` (suspend до конца фразы, отмена обрывает звук), `release()` (очередь пуста — отпустить аудиофокус/сессию).
- Таймаут фразы — в `QueuedSpeaker`: `SpeechTimeout.of(text)` (8 с + 150 мс на символ, ~2× темпа речи); не уложился — фраза обрывается, `SpeechEngine.reset()` (Android пересоздаёт `TextToSpeech`: упавший нативный движок не шлёт ни `onDone`, ни `onError`; iOS — снимает ожидание), очередь идёт дальше, `release()` — когда очередь пуста. Android: `onError`/`onStop` завершают фразу; iOS: `didCancelSpeechUtterance` и начало прерывания аудиосессии (`AVAudioSessionInterruptionNotification`) завершают фразу.
- Ленивый старт: движок не трогается при старте приложения; `prepare()` — при первом чтении `availability` или первой фразе. До проверки голоса `availability` = `Ready` (кроме Linux — сразу `Unsupported`), потом уточняется.
- Язык — язык приложения: `AppLocaleStore.current()` (`core/localization`), читается при создании `Speaker`; смена языка — перезапуском, как у всего приложения.
- Android — `TextToSpeech` (init асинхронный, фразы ждут в общей очереди; ошибка init → `Unsupported`; `setLanguage` → `LANG_MISSING_DATA`/`LANG_NOT_SUPPORTED` → `NoVoice(canInstall = true)`, язык перепроверяется перед следующей фразой — после установки голоса перезапуск не нужен). `AudioAttributes` `USAGE_ASSISTANCE_NAVIGATION_GUIDANCE`, фокус `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK` на всю очередь (`SpeechAudioFocus`, < API 26 — устаревший `requestAudioFocus`). Манифест модуля — `<queries>` `TTS_SERVICE` (Android 11+ без него движок не виден).
- iOS — `AVSpeechSynthesizer`, голос `AVSpeechSynthesisVoice.voiceWithLanguage` или первый с языком из `speechVoices()`; нет — `NoVoice(canInstall = false)`. `AVAudioSession` `playback` + `duckOthers` (говорим и на беззвучном), после очереди — `setActive(false, notifyOthersOnDeactivation)`.
- Desktop — процесс ОС на `io`, текст — в stdin (не в аргументы и не в shell-строку), `stop()`/FLUSH убивают процесс. macOS — `say -v <голос> -f -`, голос — из `say -v '?'` (`DesktopSpeechCommands.sayVoiceFor`: предпочтительные Milena/Samantha, затем основной регион, «звуковые» голоса Bells/Zarvox… — последними); нет голоса языка → `NoVoice(false)`, нет `say` → `Unsupported`. Windows — PowerShell `-EncodedCommand` со скриптом `System.Speech.Synthesis.SpeechSynthesizer`, голос по `Culture.TwoLetterISOLanguageName` (проба — код выхода 3 = нет голоса). Linux и прочее — `Unsupported` (кнопку не показываем).
- Уход приложения в фон — `stop()` в самом `Speaker`: `QueuedSpeaker(stopRequests)`, в `speechModule` — `AppLifecycle.events` `BACKGROUND` (`core/lifecycle`; desktop событий не шлёт). Экраны о фоне не заботятся; уход с экрана (`onCleared`) и выключение флага — `stop()` во VM экранов.
- `HandsFreeSettings` (`enabled: StateFlow<Boolean>`, `setEnabled`; `tipShown: StateFlow<Boolean>`, `markTipShown()` — подсказка первого включения показана, один раз на установку) — `AppSettingsFactory("handsfree")`, ключи `enabled`, `tip_shown`, по умолчанию выключено; не привязан к аккаунту.
- Подключение: `speechModule` — только `composeApp` (`AppKoinModules`); во `flasherApp` экранов обхода/Clone/проверки нет — не подключён.
- Нейросетевой голос (Android, desktop macOS/Windows; язык приложения `ru`): `RoutingSpeechEngine` — `PiperSpeech`, а системный движок — запасной: модель не поднялась, во фразе незнакомое слово/знак или ошибка синтеза/воспроизведения → фраза **целиком** системным голосом (голоса внутри фразы не смешиваются; лог `Unknown token`). `en` и iOS — только системный (iOS-рантайм — этап 6 задачи). `availability` (живёт, пока на неё подписаны — UI собирает её): Piper `READY` → `Ready` даже без системного голоса, иначе — системного движка. Сборка — `di/withNeuralVoice` (общий), платформы дают плеер и загрузчик.
- Piper: модель `ru_RU-dmitri-medium` (`rhasspy/piper-voices`, новая версия от hifi_tts_92; не копия из пакетов sherpa — та от lessac). Рантайм — `onnxruntime` Java API (`com.microsoft.onnxruntime:onnxruntime-android` / `:onnxruntime`, 1.23.x — последняя с `osx-x64` в JVM-артефакте): sherpa-onnx 2.x оригинальную модель не грузит (нет метаданных `sample_rate`…). Вход `input` (int64 ID), `input_lengths`, `scales` (`noise_scale`, `length_scale`, `noise_w` из `.onnx.json`), выход — float PCM 22 050 Гц → int16. Синтез — по предложениям на `default`, загрузка — лениво на `io` (первая фраза или `prepare()`), модель — в direct `ByteBuffer`, не в кучу.
- Общий код Android и desktop — source set `jvmAndAndroidMain` (группа иерархии в `build.gradle.kts`, onnxruntime там `compileOnly`, реальный артефакт — в `androidMain`/`jvmMain`): `OrtPiperModel` и ресурсы `piper/` (модель, `.onnx.json`, словарь). Consumer-правило R8 — `consumer-rules.pro` (onnxruntime ищет классы через JNI).
- Модель в git не хранится: задача `downloadPiperVoice` скачивает `.onnx` и `.onnx.json` с Hugging Face по закреплённой ревизии (`piperVoicesRevision`) и сверяет SHA-256 (`piperVoiceFiles`), кэш — `$GRADLE_USER_HOME/caches/specmp-piper/<ревизия>/piper/` (переживает `clean`), каталог — `resources.srcDir` `jvmAndAndroidMain`. Без сети и кэша — ошибка сборки с путём для ручной укладки. Обновить модель: новая ревизия + SHA-256 (из `api/models/rhasspy/piper-voices/tree/<rev>/ru/ru_RU/dmitri/medium`, поле `lfs.oid` у `.onnx`) в `build.gradle.kts`, проверить MODEL_CARD, перезапустить скрипт словаря.
- Воспроизведение PCM: Android — `AudioTrackPcmPlayer` (`MODE_STATIC` на предложение, те же `AudioAttributes` и `SpeechAudioFocus`, что у `TextToSpeech`, — общий экземпляр), desktop — `SourceDataLinePcmPlayer` (16 бит, кусками по полбуфера). Конец звука — `awaitPlayed` (опрос позиции, отменяемый): отмена корутины обрывает звук.
- G2P — `RussianG2p` (commonMain), без espeak-ng (GPL) в приложении: словарь `jvmAndAndroidMain/resources/piper/ru_lexicon.tsv` — `слово<TAB>фонемы[<TAB>в конце клаузы]` и `слово следующее<TAB>фонемы` (форма перед конкретным словом: оглушение/озвончение, как у espeak), фонемы в NFD; клаузы/терминаторы/предложения — как espeak в piper (знак рвёт клаузу, только если за ним пробел; `—`/`–` → `;`; точка перед строчной — сокращение). `PiperPhonemeIds` — формат piper-phonemize: `^`, `_` после каждой фонемы, `$`, гласные кластеры — один токен. Чисел, сокращений и правил чтения нет — этап 5.
- Словарь генерирует `scripts/speech/piper_lexicon.py` (вручную, на машине разработчика; venv с `pip install piper-tts`, модель — в кэше Gradle): вход — строки `values-ru` по `KEY_PATTERNS`, `scripts/speech/phrases.txt` и рукописные исключения `scripts/speech/exceptions.tsv` (`слово<TAB>написание для espeak`, ударение U+0301: «иммобилайзера», `CAN` → «кан»); выход — словарь и эталон `jvmTest/resources/piper/reference.tsv` (ID самого piper). Новые строки озвучки — ключи в `KEY_PATTERNS` (сейчас `autostart_`, `devicestate_(zone|fast)_`, `fastmount_check_`, `fastmount_voice_`) или фразы в `phrases.txt` (там же склейки шаблонов, например этапы Clone целиком), перезапуск; цифры словарь знает только встреченные во фразах (`Этап 1 из 5`, `пройдено 9 из 10`) — другие числа уводят фразу в системный голос до этапа 5; скрипт печатает расхождения с piper (должно быть 0). Словарь — вывод espeak-ng: юридическая проверка — этап 9 задачи.
- Тесты: `QueuedSpeakerTest`, `SpeechTimeoutTest`, `RoutingSpeechEngineTest`, `RussianG2pTest`, `PiperPhonemeIdsTest` (commonTest, локальный `RecordingSpeechEngine` — `core/testing` зависит от модуля), `PiperReferenceTest` (jvmTest: ID == piper для всех фраз эталона, исключения, синтез реальной моделью), `DesktopSpeechCommandsTest`/`DesktopSpeechEngineTest` (jvmTest).
