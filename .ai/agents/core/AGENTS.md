# core

- Область: core-модули проекта.
- Перед изменениями читай `docs/architecture.md` (границы и зависимости `core`-модулей) и `docs/patterns.md` → «Core».
- Для сети переходи в `core/network/AGENTS.md`; для UI-слоя — в `core/ui/AGENTS.md`; для жизненного цикла приложения — в `core/lifecycle/AGENTS.md`; для push-уведомлений — в `core/push/AGENTS.md` (вендорные SDK — `core/push-fcm/AGENTS.md`); для общих тестовых дублёров — в `core/testing/AGENTS.md`.
- Если меняешь публичные возможности `core`-модулей, обновляй этот `AGENTS.md` (или вложенный модуля) и соответствующий тематический документ в `docs/`.
- Публичные top-level хелперы `core/common` и `core.ui.lce` заводятся только под реальный вызов из другого модуля или файла (тесты своего модуля не в счёт); хелпер без вызовов удаляется вместе со своим тестом (Konsist `core-helper-usage`).
- `core/common/file`: `safeFileName` / `uniqueFileName` (имена файлов извне → безопасный basename), Android — `queryNameAndSize` и `Context.copyToCache` (копия документа SAF в `cacheDir`). Общие для пикеров `composeApp` и `feature:device:firmware`.
- `core/common/di/platformSettings` — единственный платформенный `Settings()` процесса (detekt `SettingsInstantiation`): поверх него `AppSettingsFactory` (хранилища фич с префиксом), напрямую — только язык (`core/localization`) и тема (`core/ui`) до старта Koin, ключи без префикса (`docs/patterns.md`, «Хранение настроек»).
- `core/common/layout/PaneWidthStore` — ширины перетаскиваемых панелей широкой раскладки по ключу `<фича>.<панель>` (`AppSettingsFactory("panewidths")`, `commonModule`; не привязано к аккаунту — переживает выход). Ручка — `CmpResizeHandle` (`core/ui`), сохраняет ширину VM экрана по окончании перетаскивания.
- `core/common/phone/PhoneNumbers`: телефон в международном формате — значение только цифры с кодом страны (`79001234567`), `fromRaw` (вставка, профиль; `8XXXXXXXXXX` → `7…`), `fromInput`, `format` (маски стран Европы и СНГ, прочие — группы по 3), `isValid` (длины по странам; ⊂ регулярки старого desktop), `toE164`. UI-поле — `CmpPhoneField` (`core/ui`). Потребитель — `feature/tech-requests`.
- `core/common/AppStore` (`GOOGLE_PLAY`, `APP_GALLERY`) — магазин Android-сборки; привязывает модуль флейвора `androidApp` (`storeModules()`), на iOS/desktop и во flasher не привязан (`getOrNull`). Потребители: ссылки обновления (`composeApp` Android), `DeviceType` для сервера (`core/specialist`).
- `core/common/time`: `TimeZoneSource` (пояс на вызов, `System`/`fixed(tz)`); `commonModule` привязывает `kotlinx.datetime.Clock` и `TimeZoneSource` — production берёт «сейчас» только из них (detekt `DirectClockUsage`, `docs/patterns.md` → «Источник времени»). `core/common` отдаёт `kotlinx-datetime` через `api`.
- `core/common/coroutines/ServiceScope.kt` — `serviceScope(dispatcher, logTag, parent)`: `SupervisorJob()` + диспетчер + логирующий обработчик. Scope синглтона создаёт Koin-модуль и передаёт в конструктор (`appScope` в `commonModule`, `DeviceSessionImpl`); `parent` — только тесты. Голый `CoroutineScope(…)` вне `di` — detekt `UnmanagedCoroutineScope` (`docs/patterns.md` → «Конкурентность»).
- `core/permissions`: `PermissionsProvider` (Koin, `permissionsModule()`) — единственная точка доступа к разрешениям и состоянию радио: `requestBlePermissions()` и `requestCameraPermission()` → `PermissionResult` (`Granted` / `Denied(canOpenSettings)`), `deviceAccessRequirements()`, `isBluetoothEnabled()`, `isLocationEnabled()`, открытие системных настроек. Типы библиотеки разрешений (`ru.alarmtrade.permissions.*`) наружу из модуля не выходят — фичи их не импортируют; платформенные `expect` — `internal`.
- `core/barcode`: сканер штрих-кода — `BarcodeScanner(access, accept, onResult, …)` (полноэкранный слой: камера, рамка, лазер, фонарик, «Ввести вручную», подсказка через 8 с, отклик «распознано», состояния без доступа/без камеры), `isBarcodeScanAvailable`, `digitsOf`. Камера и распознавание — только здесь: Android — CameraX `LifecycleCameraController` + `MlKitAnalyzer` + ML Kit barcode (модель в APK, без GMS), iOS — AVFoundation (`AVCaptureMetadataOutput`, `rectOfInterest`), desktop — нет. Разрешение запрашивает вызывающий через `core/permissions`; код читается только внутри рамки и засчитывается по 2 кадрам подряд (`ScanStabilizer`); тап в рамке — фокус и экспозиция в точку (`FocusRequest`: CameraX `startFocusAndMetering`, iOS `focusPointOfInterest`) с кольцом-откликом — встроенный tap-to-focus `PreviewView` не срабатывает, нажатия забирает слой. Цвета слоя камеры — `cmpDomainColors().camera*`. Манифест Android — `CAMERA` + `uses-feature camera required=false`, iOS — `NSCameraUsageDescription`.
- `core/files`: импорт/экспорт текстового файла через системный диалог — `TextFilePicker.pick(type)` → `TextFilePickResult` (`Picked(name, text)` / `Cancelled` / `TooLarge` / `Failed`), `TextFileSaver.save(suggestedName, type, text)` → `TextFileSaveResult` (`Saved(name)` / `Cancelled` / `Failed`); `TextFileType` (расширение, MIME, UTI, MIME для выбора, `maxBytes` — по умолчанию 1 МиБ, ограничивает только выбор файла, не сохранение), готовые `TextFileType.Json` и `TextFileType.Txt` (`text/plain`, `public.plain-text`). Создаются `rememberTextFilePicker(dispatchers)` / `rememberTextFileSaver(dispatchers)` (Android — SAF `OpenDocument`/`ACTION_CREATE_DOCUMENT`, запись `wt`; desktop — `JFileChooser`; iOS — `UIDocumentPickerViewController` import/export). Диалог — на main, чтение/запись и UTF-8 (BOM срезается, битая кодировка — `Failed`) — на `io`; имя сохранения — безопасный basename с расширением типа. `AppDispatchers` фича получает параметром из корня (`koinInject` — только корни), порт передаёт во VM через `parametersOf` (разрешён Konsist `view-model-dependencies`). Ожидание результата на Android переживает поворот экрана, но не смерть процесса — пользователь повторит выбор. Порт для `.json`/текста фичи свой не заводят.
- `core/files` — изображения, два шага: `ImagePicker.pick(source)` (`ImageSource.Camera`/`Gallery`) → `ImagePickResult` (`Picked(PickedImage)` / `Cancelled` / `Failed`), затем `prepare(image, crop)` → `ImagePrepareResult` (`Prepared(bytes, name, mimeType)` / `Failed`); `canTakePhoto` — есть ли камера (desktop — `false`: сразу файл). `PickedImage` — JPEG ≤ 2048 px, уже повёрнутый по EXIF, и `preview: ImageBitmap`, декодированный из этих байтов общим `decodeToImageBitmap` (вне main): обрезка задаётся в его пикселях (`ImageCropRect` с размером изображения; при другом размере пересчитывается пропорционально, `cropRegion`). `prepare` — обрезка → большая сторона ≤ 800 px (не увеличивается) → JPEG 85, имя — исходное с `.jpg`, иначе `image.jpg`. Геометрия экрана обрезки под круглый аватар — `ImageCropGeometry` (чистая, тесты): масштаб от «изображение закрывает квадрат» до ×4, сдвиг без пустоты в квадрате, старт по центру, перевод в `ImageCropRect`. Создаётся `rememberImagePicker(dispatchers)`, во VM — через `parametersOf` (Konsist `view-model-dependencies`). Платформы: Android — Photo Picker `PickVisualMedia(ImageOnly)` и `TakePicture` во временный файл `cache/image-capture/` через свой `ImageCaptureFileProvider` `${applicationId}.core.files.images` (второй стандартный `FileProvider` склейка манифестов не допускает; файл удаляется после чтения), `BitmapFactory` с `inSampleSize`, поворот по EXIF, прозрачное — на белом; iOS — `PHPickerViewController` (без разрешения на фото) и `UIImagePickerController` с камерой, `UIGraphicsImageRenderer` (ориентация учтена, обрезка — сдвигом рисунка) и `UIImageJPEGRepresentation`; desktop — `JFileChooser` (jpg/png/gif/bmp) и `ImageIO`, EXIF не учитывается. Разрешение камеры (на Android оно объявлено в манифесте — без него `TakePicture` падает) запрашивает вызывающий через `PermissionsProvider.requestCameraPermission()`. Ожидание результата на Android — общий `ResultRequester`.
- Сборка модулей — convention-плагины `build-logic`: `id("specmp.kmp.library")` или `id("specmp.kmp.compose")` (Android-only модули вендорных SDK — `id("specmp.kmp.android")`) (таргеты, JVM 17, SDK, namespace из пути); в `build.gradle.kts` модуля — только iOS-framework, `compose.resources` и зависимости (`docs/build.md` → «Convention-плагины»).
