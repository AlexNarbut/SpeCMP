# composeApp

- Область: `App()`, навигация, общая UI-интеграция и подключение feature-модулей в `composeApp`.
- Перед изменениями читай `docs/navigation.md`; для общих Compose-паттернов и производительности — `docs/compose-best-prac.md`.
- Для правил UI-компонентов переходи в `core/ui/AGENTS.md`; для устройства feature-модулей — в `feature/AGENTS.md`.
- Если меняешь структуру `App()`, навигацию или способ интеграции фич, обновляй `docs/navigation.md` и связанные разделы `docs/architecture.md`.
- Koin-модули приложения — `di/AppKoinModules.kt` (`appKoinModules(versionName, versionCode)`; платформенные — `rememberPlatformKoinModules()`); полноту графа проверяет `jvmTest` `AppKoinModulesTest` (koin-test `verify`, `docs/patterns.md` → «Внедрение зависимостей»): новый модуль — в список, новый параметр `parametersOf` или платформенный тип — в тест.
- Адаптеры портов ассистента монтажа (`assistant/AssistantPortAdapters.kt`, `di/AssistantPortsModule.kt`) связывают `feature/mount-assistant` с `firmware`/`autostart`/`state`; навигация ассистента — `navigation/AssistantWiring.kt` (`feature/mount-assistant/AGENTS.md`).
- Process-wide сервисы фич (`start()` доменных сервисов, сейчас `DeviceSession`) запускает `AppServicesStarter` (`core/common`): слоты — `di/AppServicesModule.kt`, `start()` — из `AppStartViewModel` (`core/ui`). Новый сервис со `start()` — новый слот (и во `flasherApp`, если фича там есть). См. `docs/patterns.md`, «Доменные сервисы».
- Push: `navigation/PushOpenWiring.kt` (`PushOpenEffect` — тап из уведомления → чат поверх / ссылка) и `ChatNotificationsEffect(isChatOnTop)` (expect) — оба в `AuthedNavGraph`, живут с авторизованной зоной. Desktop (`jvmMain`): composable создаёт `push/DesktopChatNotifier` (порт `SupportChatNotifier` фичи чата) и отдаёт его в `SupportChatNotificationsEntry` — подписку на `SupportChatRepository.session()`, проверку разрешения и диалог ведёт `SupportChatNotificationsViewModel` (живёт с хранилищем VM авторизованной зоны); notifier — бейдж и внимание в Dock/панели задач; баннер: Windows/Linux — `TrayIcon.displayMessage` (клик по баннеру/иконке трея → окно вперёд + `PushOpenRequests.open(Chat)`), macOS в собранном `.app` — нативный баннер `UNUserNotificationCenter` (`push/MacNativeNotifications`: JNA → `libspecmp_notifications.dylib` из `compose.application.resources.dir`, клик по баннеру — через `push/MacNativeBridge` с данными push чата; системный запрос разрешения — один раз, при старте notifier'а; если уведомления запрещены — диалог «Уведомления выключены» → «Открыть настройки» (раздел уведомлений приложения) на каждом входе в авторизованную зону), вне `.app` (`gradle run` — без бандла API недоступен) — `osascript display notification` (`TrayIcon.displayMessage` на macOS ничего не показывает; баннер от «Редактора скриптов», клик не доходит); на macOS чат открывает и клик по иконке в Dock, пока есть непросмотренные; не показывает, если окно в фокусе и открыт чат. Соединение чата держится, пока пользователь в аккаунте (SDK считает подписчиков — с экраном чата одно соединение). Android/iOS — пусто (там push). macOS push: `push/MacNativeBridge` (`install()` из `desktopApp` `main()` до окна — клик, запустивший приложение, не теряется; загружает dylib, ставит делегат уведомлений, клик → окно вперёд + `DesktopPush.onNotificationOpened`) и `push/MacMessagingClient` (`DesktopMessagingClient` над `MacNativeLibrary`). iOS-мост для Swift — `iosMain/push/PushBridge.kt`.
- Запуск приложения — `AppStartViewModel` (`core/ui`, `koinViewModel` в `App()`; регистрация — `di/AppServicesModule.kt`): `AppServicesStarter.start()` и `AppStartup.start(языкПриложения)` в `onStart`, UI — по `isReady`. Сервисы в composable корня не берутся (detekt `ServiceInComposable`); исключения с `@Suppress` — `PermissionsProvider` для `BindEffect` и `TimeZoneSource` для `LocalTimeZoneSource`.
