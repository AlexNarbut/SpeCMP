# desktopApp

- Область: JVM entry point, desktop window, packaging и platform bootstrap в `desktopApp`.
- Перед изменениями читай `docs/build.md`.
- Общую UI- и бизнес-логику ищи в KMP-модулях, а не в `desktopApp`.
- USB на macOS arm64: `usb4java` (SDK) работает только на x86_64-JDK — JDK запуска задаёт `compose.jvmHome` (`-P` или `local.properties`), а без него `desktopApp/build.gradle.kts` сам выбирает установленный x86_64-JDK 17 (`java_home -a x86_64 -v 17`), см. `docs/build.md`. Запуск из IDE — Run-конфигурация `desktopApp` (`.run/desktopApp.run.xml`, Gradle `:desktopApp:run`), не `main()` из гуттера.
- Пакет ставится **поверх старого desktop «Pandora Spec»**: `packageName = "Pandora Spec"`, macOS `bundleID = ru.alarmtrade.specialist`, Windows `upgradeUuid = CDF66F6C-…`, `perUserInstall`, без выбора папки. Не менять: старый апдейтер открывает `/Applications/Pandora Spec.app` и в канале Windows принимает только `.exe` (поэтому собирается и `Exe`), а `versionCode` должен быть больше старого (desktop 248, Android в Play 739 — версия общая, сейчас 10.0.0 / 1000). Подпись и нотаризация macOS — если в `local.properties` есть `mac.signIdentity` (+ `appleID`, `appleIDPassword`, `appleTeamId`). Автообновление — `feature/app-update`.
- Нативные баннеры и push macOS: SwiftPM-пакет `native/macos` (`Package.swift` + `Package.resolved`, FirebaseMessaging той же версии, что у iosApp; `Sources/SpecMpNotifications/Notifications.swift` — C ABI для JNA: `install` — делегат `UNUserNotificationCenter` (клик → id + `userInfo` JSON, решение о показе удалённого push при открытом приложении — колбэк в Kotlin), `request_authorization`, `status`, `open_settings`, `show` (с `userInfo`), `remove_all`; `Push.swift` — `push_configure` (Firebase из `GoogleService-Info.plist`, колбэки APNs добавляются в класс делегата NSApp от AWT, поэтому — при первом запросе токена, когда окно уже создано), `push_token`, `push_delete_token`) → задача `buildMacNotifications` (`native/macos/build.sh`: `swift build` arm64 + x86_64 в `build/swiftpm`, macOS 12+; рядом копируется `iosApp/iosApp/GoogleService-Info.plist` — bundle ID общий) → `nativeAppResources/macos` = `appResourcesRootDir` → `Pandora Spec.app/Contents/app/resources/`. Собирается только на Mac (`onlyIf`), `prepareAppResources` зависит от неё. Работает только в `.app` (проверка бандла); подпись — `build.sh` сам вызывает `codesign --options runtime --timestamp` идентичностью `mac.signIdentity` (вход задачи), иначе остаётся ad-hoc линкера. `Info.plist`: `FirebaseAppDelegateProxyEnabled = false`.
- Push macOS (APNs → FCM) — у любой подписанной сборки (`mac.signIdentity`): профиль Developer ID для `ru.alarmtrade.specialist` (`aps-environment = production`) лежит в репозитории — `macos/embedded.provisionprofile` (не секрет: он есть в каждом `.app`; секрет — только закрытый ключ сертификата). Главный бинарник — `macos/push.entitlements`, после `createDistributable`/`createReleaseDistributable` профиль копируется в `Contents/embedded.provisionprofile` (у jpackage JDK 17 нет `--app-content`) и бандл переподписывается. `verifyMacPushSigning` перед этим сверяет SHA-1 сертификата `mac.signIdentity` (`security find-identity`) с сертификатами профиля: с push-entitlement и чужим сертификатом macOS не запустит приложение. Перевыпустили сертификат Developer ID — перевыпусти профиль с ним и замени файл. Без подписи push нет (entitlement не ставится). APNs-ключ — в Firebase (`pandora-specialist-6663f`, слот Production).

- Windows: рендер Skiko — OpenGL (`useOpenGlOnWindows()` в `Main.kt`, `skiko.renderApi`): на DirectX окно виснет при прокрутке. Заданный вручную `SKIKO_RENDER_API`/`-Dskiko.renderApi` не перебивается.
