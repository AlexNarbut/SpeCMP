# feature/mount-passport

- Обособленная фича **«Паспорт монтажа»**: список паспортов блока, архив (все + поиск), считывание блока, предотчёт (редактируемый паспорт), «Паспорт оформлен» (PDF), паспорт без блока (экран «Блок»). domain + data + presentation в одном модуле; потребителей логики вне модуля нет. ТЗ — `.claude/tasks/mount-passport.md` (раздел «Реализация — решения владельца 2026-11-20» главнее), макет — `design/features/mount-passport/` (`PassportList.jsx`, `PassportEditor.jsx` вариант 2a, `PassportRead.jsx`, `PassportReady.jsx`, `PassportDoc.jsx`).
- **Вся бизнес-логика — в SDK** (`MountPassportInteractor`, `alarmtrade-common3` `specialist` ≥ 1.2.23): хранение папками, индекс и поиск (нормализация госномера/VIN/телефона), номер, запоминание организации/адреса, лимит 8 фото. Фича её не дублирует: `data/datasource/MountPassportDataSource` — только делегирование, `SpecialistMountPassportRepository` — запросы, маппинг SDK → domain (пути фото — абсолютные: папка из `getFiles` + относительный путь SDK) и ошибки фото: `MountPassportPhotoLimitException` → `PassportPhotoLimitException`, нехватка места (`ENOSPC`/«No space left» в цепочке причин — SDK её не различает) → `PassportStorageFullException`.
- «Мои конфигурации» — порт `PassportConfigurationsRepository` (фича от `feature/configurator` не зависит), адаптер `composeApp/mountpassport/AppPassportConfigurationsRepository` (`LocalConfigurationsRepository.create(…, SettingsSource.File(settings.dxs, inPlace = false))`), модуль `mountPassportPortsModule`. «Сохранить в файл» — общий `SettingsFileSaver` (`feature/device/presentation-core`) по пути `settings.dxs` из `getFiles`.
- **Входы** (`presentation/navigation/MountPassportEntries.kt`): маршруты `MountPassportArchiveRoute` / `MountPassportUnitRoute(systemId)` / `MountPassportEditorRoute(passportId)` / `MountPassportReadRoute(source: MountPassportReadRouteSource = AdvancedMount | Complete(passportId))` и `MountPassportArchiveEntry` / `MountPassportUnitEntry` / `MountPassportEditorEntry(…, callbacks, ports)` / `MountPassportReadEntry(source: PassportReadSource, onDone(passportId), onCancel)` (быстрый монтаж встраивает его слотом с `PassportReadSource.FastMount(PassportFastMountResult)` — в маршрут итог мастера не кладётся). Внутри — свой nav3-граф (`MountPassportNavGraph`): список → предотчёт → «Паспорт оформлен» (`PassportReadyKey`), архив → «Блок» (`PassportLookupKey`) → предотчёт с заменой. `MountPassportCallbacks` — только переходы в считывание: `onNewPassport(systemId)`, `onFinish(id)` («Дооформить»), `onReadUnit(id)` («Считать блок»); `MountPassportPorts` — `ImagePicker`, `SettingsFileSaver`, `HtmlPdfRenderer`, `PdfPageRasterizer`, `BinaryFileExporter`, `BinaryFilePicker` из корня. Обвязка — `composeApp/navigation/MountPassportWiring.kt`: колбэки → `MountPassportReadRoute`, по готовности считывание заменяется `MountPassportEditorRoute` (`replaceCurrent`), «Отмена» — `popSafe`. Исполнитель (имя, телефон/email) — порт `PassportInstallerRepository`, адаптер `composeApp/mountpassport/AppPassportInstallerRepository` над `AccountRepository` (ожидание профиля ≤ 3 с).
- **Входы снаружи**: финал быстрого монтажа — `MountPassportReadEntry(PassportReadSource.FastMount)`,
  `MountPassportEditorEntry(passportId, callbacks(onBack = на финал), ports)` и `MountPassportExportEntry(passportId,
  ports) { MountPassportExportActions -> … }` слотом `MountPassportSlot` (`composeApp/navigation/FastMountWiring.kt`):
  экспорт оборачивает финал — отдаёт «Экспорт PDF» (`onExportPdf`, `exportingPdf`) / «Экспорт ZIP» (`onExportZip`)
  через свою VM переноса (`PassportExportHost`, ключ `export-<id>`), поверх — лист/диалог переноса и снекбар;
  `createBlank(PassportFastMountResult)` — заготовка `BLANK` из итога мастера без считывания
  (`MountPassportDraftSource(origin = FAST_MOUNT, status = BLANK)` SDK `createMountPassportUseCase`; без блока —
  ошибка). Расширенный монтаж — плитка `MountSection.MOUNT_PASSPORT` (перед «Заявками», без `needsCan`, все
  транспорты, иконка `mount_section_mount_passport.xml`) → `MountPassportUnitRoute(systemId)` в **корневой**
  навигации: обёртка блока (`DeviceInteractionHost`) не в композиции и потерей связи считывание не перекрывает —
  обрыв показывает само считывание (остановка «Связь потеряна»), сессия блока живёт (VM обёртки — в записи
  `AdvancedMountRoute`). Главная — плитка «Паспорта монтажа» → `MountPassportArchiveRoute`. Ассистент — плитка и
  последний шаг → `MountPassportReadRoute(AdvancedMount)` или `MountPassportEditorRoute(id)` (оформленный сегодня —
  `lastOfUnitToday`).
- **Считывание** (`PassportReadViewModel`, данные — `PassportReadingRepository` → `SpecialistPassportReadingRepository`): старт в `onStart` — исполнитель из профиля (ошибка — пустой) → `read(source, installer)`; этапы/фазы SDK мапятся в domain (`PassportReadState`, `PassportReadPhase`); остановки (`ReadStop`: блок не прочитан, связь потеряна, не на связи, другой блок, не сохранилось, ошибка потока) — команды `RETRY`/`CONTINUE_WITHOUT`/`SKIP` в SDK; ошибка потока — «Повторить» перезапускает сбор. Таймер этапа «Настройки» — пока он `Reading`. «Отмена» и «Назад» — отмена сбора, записи нет. `Done(passportId)` — пауза 900 мс («Всё прочитано»), затем эффект `Done` один раз.
- **«Перечитать»** — во VM предотчёта (`onReread` → `rereadMountPassportStageUseCase`): прогресс `rereading` на кнопке, повтор во время чтения игнорируется; `PassportUnitMismatchException` / `PassportStageNotReadException` → снекбар. Предотчёт подписан на индекс (`observeAll`, `updatedAt` паспорта): изменили снаружи (считывание, «Паспорт оформлен») и своих несохранённых правок нет — перечитывает паспорт.
- **Документ**: тексты — `PassportDocumentLocalizer` (реализация `ResourcePassportDocumentLocalizer`, ключи `mountpassport_document_*`, месяцы — `common_date_label_months`, язык/шаблон даты/разделитель разрядов — тоже ресурсы, пояс — `TimeZoneSource`); domain — `PassportDocumentText` (все поля `MountPassportDocumentStrings`) + `PassportDeviceKind` (виды устройств; маппинг `DeviceType` SDK → вид — в data). Фото — `EMBEDDED`.
- **Кнопки документа — единая схема для всех платформ** (решение владельца 2026-11-20). Шапка предотчёта: «←», «Паспорт монтажа» + «№ · дата», «Сохранено». Главная кнопка (`MountPassportTags.PDF`): черновик/заготовка — «Сформировать», `ISSUED` — «Обновить»; у `ISSUED` рядом «Экспорт PDF» / «Экспорт ZIP» (`EXPORT_PDF` / `EXPORT_ZIP`), у черновика экспорта нет. Место: телефон/узкое окно и встроенный предотчёт списка — закреплены внизу (`EditorDocumentBar`; не помещаются в ряд — экспорт строкой выше), широкое окно (≥ 840, `PassportWorkspace`) — в общей шапке (`WorkspaceDocumentActions`). Нажатие — `onCreatePdf` (проверка пропавших фото, см. «Предотчёт») → эффект `OpenDocument`: узкое окно и встроенный — экран «Паспорт оформлен» (`PassportReadyKey`), широкое — `PassportReadyViewModel.onIssue` живого листа и диалог `IssuedDialog` («Паспорт оформлен» + «№», «Экспорт PDF» / «Экспорт ZIP»; пока собирается — «Формируем документ…», экспорт недоступен, диалог не закрывается; ошибка — «Повторить»). «Экспорт PDF» — `exportPdf` (`presentation/model/PdfExport.kt`): есть `canShare` (телефон, планшет) — системное «Поделиться», иначе (desktop) — сохранить файл. В предотчёте, строке архива и на финале быстрого монтажа PDF собирает перенос (`PassportTransferViewModel.onExportPdf(id)`, `pdfExporting` — прогресс на кнопке), на «Паспорт оформлен» и в диалоге — готовый PDF VM документа. «Экспорт ZIP» — лист переноса (`onExport([id])`). Снимок настроек (в файл / в «Мои конфигурации») — только в секции «Конфигурация» предотчёта. Меню «⋯», «Открыть», «Сохранить файл», «Поделиться», «Изменить» на экранах документа нет.
- **«Паспорт оформлен»** (`PassportReadyViewModel`): `buildHtml` → `HtmlPdfRenderer.render(html, имя, PdfPageSetup(footer = «Паспорт монтажа № …» / «стр. {page} из {pages}»))` → листы `PdfPageRasterizer` по видимости (`onPageVisible`, ширина в px; смена ширины — перерисовка). PDF — в state (`PassportPdf`, `builtFor = updatedAt`): правка паспорта (новый `updatedAt` в индексе) пересобирает после 800 мс, ошибка пересборки — прежний документ + снекбар. Экран (`preview = false`): первое формирование — `markIssued` (`ISSUED`), один раз; шапка «Паспорт оформлен» + «№ …», «←» — назад в предотчёт; внизу «Экспорт PDF» и «Экспорт ZIP» (пока документ собирается — недоступны; ошибка — «Повторить»); низкое окно (< 520) — обе кнопки в шапке. Живой лист (`PassportReadyArgs.preview`, своя VM по ключу `mount-passport-preview-…`, `rememberPassportDocument`) статус сам не меняет — только `onIssue`: `issue = Forming` → сборка без кэша (переживает пересборку после правки: её финал тоже ставит `ISSUED`) → `issue = Ready` / `Failed`; `onIssueDismiss` во время сборки игнорируется, «Экспорт PDF» диалог не закрывает (решение владельца), «Экспорт ZIP» закрывает его и открывает лист переноса. Имя файла — `Паспорт_<№>_<авто (пробелы → _)|ID блока>.pdf` через `safeFileName`. Широкое окно (≥ 840) — `PassportWorkspace`: одна шапка во всю ширину («Паспорт монтажа», «№ … · дата» без времени, «Сохранено» иконкой с подписью, кнопки документа), под ней поля слева (42 %, 380–520 dp) + живой лист справа (`PassportPreviewPane`: «Предпросмотр» + «Обновляется по мере ввода…», без кнопок; низкое окно — без пометки).
- **«Блок»** (`PassportLookupViewModel`): ID — `DeviceIdQuery` (`core/common`, общий с информацией о товаре), сканер — `core/barcode` (только при `isBarcodeScanAvailable`); «Найти» → `Found` / `NotFound` / `Offline` / ошибка; не найден — модель из `getSubsystemNamesUseCase` (список грузится один раз) или «Другая — вписать»; «Далее» → `createWithoutUnit` → предотчёт вместо экрана. Серийного номера в форме нет (серийник = ID блока, решение владельца).
- **Список** (`PassportListViewModel`, `BaseDeviceViewModel`): архив — `observeAll`, блок — `observeUnit(systemId)`; поиск — поле state + `select { query }` с debounce 300 мс (пустой запрос — сразу), `flatMapLatest` отменяет прежний поиск, при изменении архива поиск повторяется. Подсветка совпадения — `presentation/model/SearchHighlight.kt` (только место в тексте: без регистра, пробелов и разделителей, «ё» = «е», латинские двойники кириллицы); строка «VIN/Клиент/Телефон: …» — когда совпадение не в заголовке строки. «Дооформить» — `BLANK` и подключён тот же блок (`canFinish`), иначе подсказка. Объём хранилища — строкой в архиве без запроса. «⋯» строки: черновик — «Открыть», «Удалить»; `ISSUED` — «Открыть», «Экспорт PDF», «Экспорт ZIP», «Удалить» (заготовка — «Открыть», если можно дооформить, и «Удалить»). Удаление — диалог подтверждения. Раскладки: Compact/Medium (по центру 720) — одна колонка, предотчёт отдельным экраном; Expanded (≥ 840) — список 400 dp + справа предотчёт выбранного (заготовка — карточка «Дооформить»).
- **Предотчёт** (`PassportEditorViewModel`): аккордеон секций в порядке документа (`sections()`: «Проверка» — только с заданиями, «Устройства» — не у паспорта без блока), раскрытые секции — `openSections` в state VM (`onSectionToggle`; переживают поворот, когда раскладка меняется между одной колонкой и «поля + живой лист»). Ручные поля — `PassportForm` в state; правки пишутся одной записью `edit` после паузы 700 мс (`launchReplacing(SAVE)`), признак `SaveStatus` в шапке; «Назад» дописывает несохранённое (`onBack` → `Close`) без подтверждения. Валидация (`PassportEditorTransitions.kt`): VIN — 17 символов без I/O/Q (ошибка длины — когда поле не в фокусе), пробег — цифры, телефон — `PhoneNumbers.isValid`; неверное значение не пишется — остаётся прежнее. Работы — галочками у расширенного монтажа и паспорта без блока, только чтение у быстрого монтажа. Автомобиль (не из мастера) — «Выбрать автомобиль» из каталога `vehicle-ui` (порт `MountPassportPorts.vehiclePicker`, слот `PassportVehiclePicker` из `composeApp/navigation/MountPassportWiring.kt`: `VehicleSelectEntry(PICK, ALL, модель блока)`, экран выбора поверх предотчёта, `vehiclePicking` в state) — заполняет поле «Автомобиль» текстом «марка модель годы» и `catalogCarId`; правка текста отвязывает от каталога (`catalogCarId = null`); вписать текстом можно всегда. «Перечитать» — только при подключённом том же блоке (`rereadVisible`), этапы `NOT_READ`/`SKIPPED`. Фото: камера/галерея (desktop — файл), `PermissionsProvider.requestCameraPermission()`, отказ → лист «Открыть настройки»; JPEG ≤ 2048 — `ImagePicker.pick`, миниатюра 320 — `prepare(…, maxSide = 320)`; лимит 8 проверяется до пикера; просмотр на весь экран (листание, подпись ≤ 60 символов с debounce, удаление с подтверждением). Недоступные фото (файла нет на устройстве — `missingPhotos` → SDK `getMountPassportMissingPhotosUseCase`): `unavailablePhotos` в state обновляется при загрузке/перечитывании и перед PDF; плитка — «Фото недоступно» + удаление (подтверждение вне просмотра). «Сформировать» / «Обновить» — `onCreatePdf` во VM: проверка до формирования документа; есть пропавшие — диалог «N фото не найдены» (`missingPhotosDialog`): «Удалить из паспорта» удаляет их и открывает документ, «Продолжить» — документ без них, закрытие — ничего; ошибка проверки — документ открывается. Переход — эффект `OpenDocument`. SDK `buildMountPassportHtmlUseCase` отдаёт `MountPassportHtmlDocument` — репозиторий берёт `html`.
- **Перенос архивом** (`presentation/screen/transfer`, `PassportTransferViewModel`, данные — `PassportTransferRepository` → `SpecialistPassportTransferRepository` над use case SDK, только делегирование и маппинг; `MountPassportArchiveException` → `PassportNotArchiveException`). PDF для архива — общий `presentation/model/PassportPdfBuilder` (тот же, что у «Паспорт оформлен»: HTML SDK → `HtmlPdfRenderer` с колонтитулом, имя `Паспорт_<№>_<авто|ID>`), статус `ISSUED` экспорт не ставит. Экспорт: один (`onExport([id])` — «Экспорт ZIP» предотчёта, «⋯» строки, «Паспорт оформлен», финала быстрого монтажа), выбранные (режим выбора списка: `picking`/`picked` в `PassportListState`, выбираются только оформленные `ISSUED`), все (`onExportAll` — все `ISSUED` из `observeAll`, `fullBackup = true`); у черновиков и заготовок экспорта нет. Лист: состав (PDF и данные — замок; «Снимок настроек» — вкл., «Фото 2048 px» — выкл., размер фото — оценка ≈ 0,5 МБ/шт.) → «Поделиться» (только `canShare`) / «Сохранить файл» → сборка с прогрессом «Паспорт i из N» (по вызовам PDF-провайдера) → отправка файла **по пути** (`BinaryFileExporter.shareFile/saveFile`, в память архив не читается). Отмена/сбой отправки — фаза «Архив готов» с теми же кнопками без пересборки; успех — лист закрывается + снекбар. Эффект `ArchiveBuilt(fullBackup)` → список выходит из режима выбора и (копия всех) убирает напоминание. Импорт: `BinaryFilePicker.pick(Zip)` (копия во временную папку) → `inspect` → сводка (дубликаты одним выбором «Пропустить» по умолчанию / «Заменить»; решения — только для `exists`) → `import` (миниатюры — `ImagePicker.shrinkJpeg(…, 320)`) → итог с проблемами; список обновляется потоком SDK. Напоминание о копии — `shouldRemindBackup` при старте архива, «Позже» — `snoozeBackupReminder`. Шапка архива: телефон — «⋯» (импорт, выбор, «Экспорт всех»), шире — кнопки «Импорт»/«Экспорт». Compact — `CmpBottomSheet`, Medium+ — `CmpDialog`; на время сборки/чтения/импорта не закрывается. VM переноса — своя на экран (`rememberPassportTransfer(owner, ports)`), порты — `MountPassportPorts.filePicker` и др.
