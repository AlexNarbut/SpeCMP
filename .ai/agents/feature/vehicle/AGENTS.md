# feature/vehicle

- Каталог автомобилей: выбор автомобиля и карточка автомобиля. Пара модулей: `vehicle` (domain + data + DI, `vehicleModule`) — логика переиспользуется (настройки блока: CAN-код и подпись автомобиля; конфигуратор; архив прошивок); `vehicle-ui` — экраны и публичная точка входа. План и решения — `.claude/tasks/vehicle-select.md`; макеты — `design/features/vehicle-select`.
- Фича не про подключённый блок и от `feature/device/*` не зависит: устройство приходит в запросе (`VehicleDeviceFilter`: `Type(ALARM|MICROBOT)` — блок не подключён, `Device(deviceName)` — модель блока).
- `VehicleCatalogRepository` (тонкий, `Response<T>`): `brands` / `models` / `trims` по `CatalogQuery(catalog, device, groups)`, `card(carId, groups)`, `findByCanCode(code, device, groups)`, `summary(carId)`. Сервер отдаёт уровни целиком — без страниц и текстового поиска (поиск по названию — локальный, в UI).
- Каталоги: `ALL` — `carsInteractor` (фильтр по подсистемам устройства: для `Device` — подсистемы модели из `deviceInformationInteractor`, для `Type` — `ALARM_MAIN`/`MICROBOT_MAIN`; фильтр групп функций — на сервере, пустой набор = `null`); `WITH_CONFIGURATIONS` — `configurationInteractor` (только автомобили с конфигурациями, фильтр — модель блока, `""` = все модели; группы не поддерживаются). Карточка и поиск по CAN — всегда `carsInteractor`.
- Модель своя, без типов SDK (`data/mapper/CarMappers.kt`): `CarBus` — все 16 значений `CarBusGroup` + `UNKNOWN`, `family` (CAN / CAN_FD / LIN / BEAN / IMO / UNKNOWN) — цвет чипа; `CarCapability` (`NoData` / `Supported(note)` / `NotSupported(note)`); функции, фото, документы — по `order` сервера; пустые строки (URL картинок, описания, примечания) → `null` / отброшены.
- Недавние — `RecentVehiclesRepository` (`SettingsRecentVehiclesRepository`, `AppSettingsFactory("vehicles")`, JSON на каталог, до 5, новые первыми, битые данные — пустой список).
- SDK — через `data/datasource/VehicleCatalogDataSource` (`SpecialistVehicleCatalogDataSource` над тремя ленивыми интеракторами, `null` — недоступен на платформе); тесты — `SpecialistVehicleCatalogRepositoryTest`, `SettingsRecentVehiclesRepositoryTest` (`InMemorySettings`).

## UI (`vehicle-ui`)

- Публичное: `VehicleSelectEntry(request, onPick, onBack, onOpenFirmwareArchive?, onOpenUserManual?)`, `VehicleSelectRequest(mode VIEW|PICK, catalog, device?, firmwareCanCode?, warnOnCanMismatch)` (обычный класс), `VehicleSelectRoute(request)` для app-графа — сериализует своё зеркало запроса (`RequestKey`): domain-модели каталога (`VehicleCatalog`, `VehicleDeviceFilter`) без `@Serializable`. Результат выбора — `CarSummary` из `feature/vehicle` (другие фичи берут тип оттуда, а UI — через слоты `composeApp`). `null`-колбэки прячут кнопку «Прошивки для CAN» и переход из народных карт.
- Одна `VehicleSelectViewModel(request)` на экран; nav3-графа внутри нет: путь выбора (`CatalogSelection`), поиск, CAN-код, фильтр, вкладка карточки — в state, поэтому смена ширины окна их не сбрасывает. Шаг узкой раскладки выводится из state (`compactStep()`), «назад» — `onBack(layout)` (диалог → фильтр → фото → точка → карточка → уровень каталога → выбор типа → выход; на Expanded открытая карточка «назад» не закрывает).
- Загрузки уровней — `LCEState<T, CatalogError>` — по корутине на `CatalogLevel`, новая отменяет прежнюю; ошибка уровня не сбрасывает выбор, «Повторить» — только этот уровень. Сбой связи — по типу ошибки (`CatalogError.Common(ApiError.NoConnection)`, см. `docs/patterns.md`), на всех платформах одинаково.
- Поиск по названию — локальный по загруженному уровню (`CatalogSearch.kt`): подсветка совпадения, «марка модель» на уровне марок (`detectCombo` → модели марки отдельной загрузкой), цифры → предложение искать по CAN. CAN-поиск — после 4-й цифры; один результат открывается автоматически один раз на код. Фильтр групп функций — черновик отдельно от применённого; применение перезагружает все показанные уровни и карточку.
- Переходы (`components/Motion.kt`, все платформы): шаги узкой раскладки, колонки моделей/комплектаций и карточка меняются `FadeContent` (затухание по ключу; уходящее содержимое рисуется со своим старым state, у каждого шага своя прокрутка — прокрутка марок сохраняется); элементы ленивых списков — `fadeItem`/`fadeItems` (`animateItem`: появление, исчезновение, сдвиг; ключ обязателен). Зона поиска одной высоты в обоих режимах (поле 56 dp + строка подсказки 24 dp) — переключение «По названию / По CAN-коду» не сдвигает список.
- Миниатюры в строках квадратные: логотип марки 48 dp, фото модели / комплектации (фото модели) / результата CAN — 72 dp. Фото автомобилей везде вписываются по большей стороне (`ContentScale.Fit`) — не обрезаются.
- Модель с одной комплектацией сразу открывает карточку. Недавние пишутся при открытии карточки и при выборе.
- Раскладка (`vehicleLayoutOf`): Compact — шаги, чип типа устройства под поиском; Medium — колонки «Марки · Модели» (аккордеон комплектаций), карточка — на всё окно (max 840 dp); Expanded — колонки + карточка справа, третья колонка «Комплектации» от 1400 dp. Карточка внутри панели выбирает широкую шапку/матрицу от 640 dp. Ширину колонок (марки, модели, комплектации, результаты CAN) пользователь перетаскивает (`CmpResizeHandle`, 200 dp … 35 % окна); ширина сохраняется в `PaneWidthStore` (`vehicle.<колонка>`) через `onPaneWidthChange` VM. Списки каталога — с постоянной полосой прокрутки (`cmpVerticalScrollbar` в `CatalogList`).
- Карточка: шапка B (фото 4:3, CAN-код с копированием, бейджи возможностей с примечанием по тапу), «Важно», вкладки только непустые (функции — матрица B с чипами шин по семействам, точки подключения с галереей и полноэкранным зумом, PDF через `LocalUriHandler`, народные карты), «Выбрать» закреплена внизу. Цвета шин — `cmpDomainColors()` (core/ui), подписи шин не переводятся.
- Подключено (`composeApp`):
  - главная → «Автомобили»: `VehicleSelectRoute`, VIEW, тип устройства выбирается;
  - расширенный монтаж → раздел «Автомобили» (`MountSection.VEHICLES`, слот `vehicles` в `AdvancedMountNavGraph`): VIEW под подключённый блок — `Device(systemName)`, CAN-код прошивки (`device.can?.code`) предзаполнен в поиске по CAN; «Прошивки для CAN» в карточке открывает поверх архив основной программы блока с этим CAN-фильтром, только просмотр (`DeviceVehicles` в `AppNavigation`);
  - настройки → окно CAN-кода → «Выбрать из каталога» (слот `vehiclePicker` в `DeviceSettingsEntry`): PICK под модель блока, рисуется поверх настроек; выбор подставляет CAN-код и `carId` в черновик окна (применяется по «Готово»).
  - архив прошивок → кнопка 🚗 в поле CAN-фильтра (слот `vehiclePicker` в `FirmwareArchiveEntry` / `FirmwareBootGraph`): PICK под модель блока, результат — CAN-код и название автомобиля в фильтр архива.
- `VehicleSelectViewModel` создаётся с ключом по запросу: справочник и выбор для архива в одном владельце ViewModel не делят её.
  - конфигуратор → облачные конфигурации (слот `ConfiguratorVehiclePicker`): PICK по каталогу `WITH_CONFIGURATIONS` под модель блока (без модели — `Type(ALARM)`, все модели).
- Галерея состояний: `./gradlew :feature:vehicle-ui:jvmTest --tests '*Gallery*'` → `build/state-gallery/vehicle-select` (Compact / Medium / Expanded / 1600, светлая и тёмная).
- `testTag` — `VehicleTestTags` (`vehicle_brand_<id>`, `vehicle_model_<id>`, `vehicle_trim_<id>`, `vehicle_trim_pick_<id>`, `vehicle_can_result_<id>`, `vehicle_recent_<id>`, `vehicle_card`, `vehicle_card_pick`, `vehicle_search`, `vehicle_can_input`, `vehicle_filter*`, `vehicle_type_*`, `vehicle_tab_*`, `vehicle_point_<i>`, `vehicle_retry` …).
