# feature/main

- Авторизованная зона приложения: главный home-экран монтажника с topbar, адаптивным drawer, основными сценариями монтажа и сеткой инструментов.
- Фича содержит `presentation` и узкий `MainRepository` для startup-логики home: профиль пользователя, синхронизация версии базы и проверка обновления приложения. `MainScreenViewModel` зависит от `MainRepository` и `LogoutUseCase` (`feature/auth-state`); прямые вызовы Specialist SDK — только в `data/datasource/MainDataSource` (`SpecialistMainDataSource`, делегирование), маппинг и особые ветки — в `SpecialistMainRepository` (тест — `SpecialistMainRepositoryTest`).
- Профиль, возможности и коммерческие данные пользователя кэшируются (`data/cache/SettingsMainUserCache`, `AuthCloseable` — чистится при выходе): при старте сразу показывается кэш, сеть обновляет его поверх (`LCEState.Content.isUpdating`/`updateError`); ошибка обновления не стирает показанное. Обновление — при старте, при открытии шторки и кнопкой у профиля. Скелетон держится, только если профиля нет и в кэше (`initialRefresh`, `awaitAll`, таймаут 10 с на запрос).
- Аватар в шапке шторки — `AccountProfile.avatarUrl` (`UserContactInformation.photoUrl` SDK, уже абсолютный URL: SDK сам дописывает хост к `avatarUrlRel`; пустая строка → `null`), кэшируется вместе с профилем (`CachedProfile.avatarUrl`, по умолчанию `null` — старый кэш читается). Грузится `CmpAsyncImageWithPlaceholder` общим `ImageLoader` без авторизации; пока грузится, при ошибке и без URL — круг с инициалами (или иконкой).
- Смена аватара: тап по аватару (значок камеры, `testTag` `main_drawer_avatar`) → `MainScreenViewModel.onAvatarClicked`: есть камера — боттом-шит «Камера / Галерея» (`MainAvatarSourceSheet`, `CmpBottomSheet`), нет (desktop) — сразу файл. Выбор источника в шторке только запоминается в state (`pendingAvatarPick`); сам `ImagePicker.pick()` стартует, когда шторка ушла из композиции — `LaunchedEffect` в `MainHomeBody` → `onAvatarSourceSheetClosed` (на iOS нативный пикер, показанный из закрывающегося окна шторки, исчезает вместе с ним — CMP-10135). Пикер — `ImagePicker` (`core/files`), создаёт `composeApp` (`rememberImagePicker`) и передаёт `MainNavGraph` → `parametersOf` во VM. Выбранное изображение открывает экран обрезки `MainAvatarCropScreen` (`avatarCrop` в state; `CmpFullScreenDialog`, круглая маска над квадратом, перетаскивание, щипок, колесо мыши на desktop; геометрия — `ImageCropGeometry`): «Готово» → `onAvatarCropConfirmed(crop)` → `ImagePicker.prepare` → загрузка; «Отмена» и системный «Назад» — `onAvatarCropCancelled`, без загрузки и ошибки. Камера — после `requestCameraPermission()`, отказ — `MainAvatarError.CameraDenied`. Загрузка — `MainRepository.uploadAvatar` → `AccountRepository.uploadAvatar` → SDK `UserInteractor.uploadAvatarUseCase` (specialist ≥ 1.2.17, `POST api/Files/UploadAvatar`, ответ — абсолютный URL). Пока идёт — индикатор на аватаре и повторные нажатия игнорируются (`isAvatarUploading` + `executeWithProceedLock`); успех — новый URL сразу в state и в кэш профиля; ошибка — баннер под профилем (`avatarError`) с крестиком (`CmpBanner(onDismiss)` → `onAvatarErrorDismissed`), прежний аватар остаётся; отмена выбора — ничего. Если сервер вернул тот же URL, к нему добавляется `specmp_v=<время>` (`AvatarRevision.kt`): иначе Coil покажет старую картинку из своего кэша; при обновлении профиля метка сохраняется, пока URL сервера не сменится.
- Ручное «Обновить базу» без сети (`NetworkMonitor`, на desktop его нет) — ошибка, а не «База обновлена»: SDK при ошибке сети отдаёт `FinishedNoUpdates`. Ошибка видна и в шторке под пунктом. Синхронизация базы устройств и проверка обновления приложения идут параллельно и скелетон не держат: у них свои индикаторы вверху экрана.
- После успешного выхода экран не навигирует сам — переключение обратно на login выполняет `feature/auth-state` по обновлению состояния сессии; кнопка logout остаётся заблокированной до переключения зоны.
- Дизайн home берётся из `design/features/home` и переносится через существующий `core/ui` UI Kit; иконки карточек лежат в `composeResources/drawable` в формате Android Vector Drawable XML. Compose Multiplatform на Android не поддерживает SVG-ресурсы через `painterResource`, поэтому SVG нельзя класть в `composeResources/drawable`.
- Плитку «Чат тех. поддержки» прячет только явный ответ сервера «недоступен» (`ChatAvailability.statusCode != 0`); пока ответа нет или опрос упал (нет сети) — плитка видна, ошибка опроса не меняет уже известный ответ. Часов работы у поддержки нет.
- Карточки `Requests` и `TechSupportChat` эмитят навигационное действие в чат; сам `SupportChatRoute` подключается только в `composeApp`. В drawer перехода в чат нет.
- Строковые ресурсы модуля — `main_*` (EN/RU) в `composeResources`.
- Карточка `ProductInfo` (только при `UserAppFeature.PRODUCT_SEARCH`, `MainUserAppFeatures.hasProductSearch`) эмитит `MainNavigationTarget.ProductInfo` → `ProductInfoRoute()` (`feature/product-info`) в `composeApp`.
- **Обновление приложения** — порт `MainAppUpdateRepository` (`domain/repository`, адаптер `composeApp/appupdate/AppMainAppUpdateRepository` поверх `AppUpdateService` из `feature/app-update`): `status()`, `check()` при старте, `download()` из уведомления, закрытая плашка. Входы по макету `design/features/home/` (`subcomponents/MainHomeUpdate.kt`): desktop — пункт «Проверить обновления» (`AppUpdate`, новая проверка), блок внизу бокового меню (доступна / загрузка / «Установить» → `AppUpdateInstall` / установка), уведомление при старте один раз за сессию главного, само скрывается через 8 с; телефон и планшет — закрываемая плашка в начале главного (до следующей версии) и пункт «Обновление приложения» с точкой; значок «Нужно обновить приложение» в топбаре, когда база требует новую версию (`AppUpdatePrompt`). testTag — `MainUpdateTags`.
- Пункт «Оформление» в шторке — `MainNavigationTarget.Appearance` (`MainScreenViewModel.onAppearanceClicked`); экран `AppearanceRoute` (`feature/appearance`) подключает `composeApp`, фича от него не зависит.
