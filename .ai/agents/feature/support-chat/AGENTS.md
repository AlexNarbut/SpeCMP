# feature/support-chat

- Обособленная фича экрана **«Техподдержка»**: доменные модели и `SupportChatRepository`, SDK-маппинг, ViewModel и UI находятся внутри модуля. Точка входа — `SupportChatEntry` (`presentation/navigation`): composable без собственного nav3-графа, размещается как entry в корневом `NavDisplay` (`composeApp/AppNavigation`).
- Входы в чат: карточка `Requests`, карточка `TechSupportChat` и пункт drawer «Заявки на техпомощь»; app-level переход в `SupportChatRoute` выполняет `composeApp`.
- `SupportChatScreenViewModel` сначала подписывается на hot flow `observeEvents()`, затем открывает чат и запрашивает историю (порядок задан в `init {}`). Не меняй этот порядок: SDK публикует `MessagesPage` без replay прямо во время `loadNextMessages()` — репозиторий маршрутизирует его в ожидающий вызов, и если коллектор ещё не подписан, страница будет потеряна (до таймаута).
- Контракт истории с гарантированным финалом: `loadNextMessages(): Response<SupportChatHistoryPage>` возвращает страницу вызывающему (или ошибку/таймаут 15 с) — события `HistoryPageReceived` в домене нет. `hasMore` — эвристика «непустая страница» (SDK 1.1.76 флаг конца истории не отдаёт), риск зафиксирован в KDoc `SupportChatHistoryPage`. Контент сообщения эксклюзивен (Text | Image | Document) — подписей у вложений SDK не поддерживает.
- VM живёт в per-entry `ViewModelStore` (`rememberViewModelStoreNavEntryDecorator()` в корневом `NavDisplay`): инстанс существует ровно столько, сколько запись бэкстека. Сессия открывается в `init {}`, закрывается в `onCleared()` через application-scoped скоуп (`appScopeQualifier` в `core/common`) — `viewModelScope` к моменту `onCleared` уже отменён. Ручные поля-`Job`, `DisposableEffect` и явный сброс state при входе не нужны: новый вход = новый инстанс VM = чистое состояние. Сериализация ретраев — через `executeWithProceedLock` из `BaseViewModel`.
- `SpecialistSupportChatRepository` — Koin-синглтон, наследует `AuthCloseable` и переживает логаут: `openChat`/`closeChat` сериализованы `connectionMutex` (переплетение close старой сессии с open новой закрыло бы свежее соединение). Identity сессии не кэшируется самим репозиторием: email резолвится один раз в `openChat()` из `AccountRepository` (`core:specialist`); неуспех резолва — ошибка открытия чата (offline-баннер), а не деградация `isMine`. При логауте `LogoutUseCase` проходит по всем `AuthCloseable` и вызывает `release()` (закрытие сессии).
- Исходящая отправка формирует отдельное сообщение для каждого вложения и отдельное текстовое сообщение — контент сообщения эксклюзивен (SDK не поддерживает подпись к вложению). Тип вложения определяется источником выбора (`onImagePicked` / `onDocumentPicked`), а не содержимым: картинка, выбранная через файловый пикер, уходит документом. Единая модель вложения `SupportChatAttachment` (nullable `url`/`localPath`), отдельной pending-иерархии нет; UI получает плоскую `@Immutable` `SupportChatUiAttachment` (маппинг `toUiAttachment()` на границе экрана).
- Скачивание вложений: кнопка Download только у входящих (от поддержки) с известным url. VM через `repository.downloadFile` (SDK `filesInteractor.downloadFileUseCase`) получает байты, платформенный `SupportChatFileSaver` (presentation/platform, actual в composeApp, передаётся в конструктор VM через `parametersOf`) сохраняет в `Загрузки/Pandora Spec` (Android MediaStore, Desktop `~/Downloads`; на Android API < 29 без WRITE_EXTERNAL_STORAGE — `Failed`); на iOS байты пишутся во временный файл и экспортируются системным `UIDocumentPickerViewController` (asCopy=true) — место выбирает пользователь, отмена пикера → `Cancelled` без снекбара. Результат — `SupportChatEffect.AttachmentDownloaded/AttachmentDownloadFailed`, прогресс — `downloadingAttachmentId` в state. Известный баг SDK 1.1.76: `NetworkClient.prepareUrl` ломает query (`?`→`%3F`) для url без `%XX` → 404, а из-за отсутствия `expectSuccess` 404 приходит как `Response.Success` с пустыми байтами (сейвер пустые байты отклоняет → `Failed`).
- Офлайн-сообщения получают `Pending`; `onConnectionRetry()` и событие `ConnectionChanged(true)` повторяют очередь. Баннер Retry не должен вызывать загрузку следующей страницы истории.
- Отправку блокирует только реальный офлайн → `SupportChatOfflineBanner` с кнопкой «Повторить». Источники `isOffline`: (1) WS `ConnectionChanged(false)`; (2) ошибка `openChat`; (3) ошибки WS-событий (`Response.Error` в `observeEvents`) — на iOS обрыв сети приходит именно так (SDK мапит `onFailure` в `State.Error`, а не `Disconnected`), причём потоком ~кГц, поэтому реакция одноразовая: баннер + `closeChat`, повторные ошибки игнорируются. **Автоматических реконнектов нет**: переподключение — только вручную через `onConnectionRetry()` (одна попытка `openChat`, неудача → баннер остаётся). Коллекция событий идёт на `dispatchers.io` — кГц-шторм ошибок на main вешал UI. В SDK 1.1.76 (iosMain) оборванный сокет после первого `onFailure` становится недостижимым зомби (`clearSession` обнуляет ссылку до `closeSocket`, рекурсия `receiveMessage` крутится до рестарта процесса) — лечится только в SDK, с нашей стороны это фоновый шум. SDK `isAvailableUseCase` — бизнес-флаг поддержки (HTTP, часы работы), а НЕ индикатор соединения: состояние «чат недоступен» из приложения удалено (в дизайн-макетах его нет), не возвращай его и не гейть по нему отправку.
- Ошибки — one-shot `SupportChatEffect` через `sideEffectFlow`/`collectSideEffect`: `MessageSendFailed(messageId)` → снекбар с action Retry → `onRetry(messageId)`; `HistoryLoadFailed` → снекбар без action (только ошибки пагинации при живой ленте). Ошибка первой загрузки истории не снекбар: `history = LCEState.Error` → полноэкранный `SupportChatErrorState` с кнопкой «Повторить» (`onHistoryRetry`). Ошибки в state не хранить.
- Платформенные порты `SupportChatFilePicker`/`SupportChatFileSaver` живут в `presentation/platform` фичи, actual — в `composeApp`: Android activity-result, Desktop `JFileChooser`, iOS `UIDocumentPickerViewController`. Feature получает только `SupportChatPickedFile` с локальным путём и метаданными.
- UI следует `design/features/support-chat`: адаптивная ширина compact/medium/expanded, wallpaper с ключами, loading skeleton, empty state, tonal bubbles, статусы доставки, системные вложения и Desktop Enter / Shift+Enter.
- Пузырь сообщения обтягивает контент с потолком `maxWidthFraction` (0.82) от колонки чата (BoxWithConstraints + `widthIn(max)`), НЕ фиксированной ширины. Картинка: высота фикс 170dp, ширина по пропорциям изображения (`SubcomposeAsyncImage` + intrinsicSize + `aspectRatio`, ratio в рамках 0.75..2, дефолт 4:3 до загрузки) — пустот по бокам нет. Композер = ширина колонки чата: `fillMaxWidth().widthIn(max = columnMaxWidth)` + центрирование корневой CmpColumn.
- Строки фичи — `support_chat_*` в `composeResources` (EN/RU). UI строится через `Cmp*`; новые общие иконки добавляются в `core/ui`.
- После изменений кода запускай `:feature:support-chat:jvmTest` и полную `./gradlew build`, потому что платформенные actual-реализации компилируются только соответствующими targets.
