# feature/support-chat

- Обособленная фича экрана **«Техподдержка»**: доменные модели и `SupportChatRepository`, SDK-маппинг, ViewModel, UI и собственный nav3-граф находятся внутри модуля.
- Входы в чат: карточка `Requests`, карточка `TechSupportChat` и пункт drawer «Заявки на техпомощь»; app-level переход в `SupportChatRoute` выполняет `composeApp`.
- `SupportChatScreenViewModel` сначала подписывается на hot flow `observeEvents()`, затем открывает чат и запрашивает историю. Не меняй этот порядок: SDK публикует `MessagesPage` без replay прямо во время `loadNextMessages()`.
- Жизненный цикл чата — явная сессия `onScreenOpened()`/`onScreenDisposed()`, вызываемая из `DisposableEffect` в `SupportChatNavGraph`. VM живёт в app-level ViewModelStore (в nav3 1.1.x нет per-entry `ViewModelStoreOwner`) и переиспользуется между аккаунтами и открытиями, поэтому `onScreenOpened()` синхронно сбрасывает стейт и `markedAsReadIds`, перезапускает подписки и историю; `init {}` для сессии не использовать. Быстрый переход dispose→open отменяет незавершённый `closeChat` через общий `sessionJob`.
- `SpecialistSupportChatRepository` — Koin-синглтон, переживает логаут: `openChat`/`closeChat` сериализованы `connectionMutex` (переплетение close старой сессии с open новой закрыло бы свежее соединение), а `openChat` обнуляет кэш `currentUserEmail`, чтобы `isMine` не считалось по email прошлого аккаунта.
- Исходящая отправка формирует отдельное сообщение для каждого вложения и отдельное текстовое сообщение. Это сохраняет соответствие контракту SDK, где `sendMessage`, `sendImage` и `sendDocument` — разные операции. Тип вложения определяется источником выбора (`onImagePicked` / `onDocumentPicked`), а не содержимым: картинка, выбранная через файловый пикер, уходит документом.
- Скачивание вложений: кнопка Download только у входящих (от поддержки) с известным url. VM через `repository.downloadFile` (SDK `filesInteractor.downloadFileUseCase`) получает байты, платформенный `SupportChatFileSaver` (domain/picker, actual в composeApp) сохраняет в `Загрузки/Pandora Spec` (Android MediaStore, Desktop `~/Downloads`, iOS `Documents/Pandora Spec`; на Android API < 29 без WRITE_EXTERNAL_STORAGE вернёт null → снекбар ошибки). Результат — `SupportChatEffect.AttachmentDownloaded/AttachmentDownloadFailed`, прогресс — `downloadingAttachmentId` в state.
- Офлайн-сообщения получают `Pending`; `onConnectionRetry()` и событие `ConnectionChanged(true)` повторяют очередь. Баннер Retry не должен вызывать загрузку следующей страницы истории.
- Отправку блокирует только реальный офлайн (`isOffline` = WS `ConnectionChanged(false)` или ошибка `openChat`) → `SupportChatOfflineBanner` с реконнектом. SDK `isAvailableUseCase` — бизнес-флаг поддержки (HTTP, часы работы), а НЕ индикатор соединения: состояние «чат недоступен» из приложения удалено (в дизайн-макетах его нет), не возвращай его и не гейть по нему отправку.
- Ошибки отправки/загрузки истории — one-shot `SupportChatEffect` через `sideEffectFlow`/`collectSideEffect`: `MessageSendFailed(messageId)` → снекбар с action Retry → `onRetry(messageId)`; `HistoryLoadFailed` → снекбар без action. Ошибки в state не хранить.
- Платформенные `SupportChatFilePicker` живут в `composeApp`: Android activity-result, Desktop `JFileChooser`, iOS `UIDocumentPickerViewController`. Feature получает только `SupportChatPickedFile` с локальным путём и метаданными.
- UI следует `design/features/support-chat`: адаптивная ширина compact/medium/expanded, wallpaper с ключами, loading skeleton, empty state, tonal bubbles, статусы доставки, системные вложения и Desktop Enter / Shift+Enter.
- Пузырь сообщения обтягивает контент с потолком `maxWidthFraction` (0.82) от колонки чата (BoxWithConstraints + `widthIn(max)`), НЕ фиксированной ширины. Картинка: высота фикс 170dp, ширина по пропорциям изображения (`SubcomposeAsyncImage` + intrinsicSize + `aspectRatio`, ratio в рамках 0.75..2, дефолт 4:3 до загрузки) — пустот по бокам нет. Композер = ширина колонки чата: `fillMaxWidth().widthIn(max = columnMaxWidth)` + центрирование корневой CmpColumn.
- Строки фичи — `support_chat_*` в `composeResources` (EN/RU). UI строится через `Cmp*`; новые общие иконки добавляются в `core/ui`.
- После изменений кода запускай `:feature:support-chat:jvmTest` и полную `./gradlew build`, потому что платформенные actual-реализации компилируются только соответствующими targets.
