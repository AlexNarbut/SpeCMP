# feature/device/presentation-core

- Общий presentation фич устройства, без экранов; DI — только `di/handsFreeVoiceModule` (VM кнопки «Озвучка», подключает `composeApp`): его подключают фичи устройства (`device:{autostart,firmware,state,settings-ui}`, `advanced-mount`, `fast-mount`, `configurator-ui`) вместо чужих `-ui` модулей. Сам не зависит ни от одного `*-ui` (graph-assert). Пакет — `ru.alarmtrade.specmp.feature.device.presentation.core`.
- `api`: `core:ui` (супертип `BaseViewModel`), `feature:device:interaction` (`DeviceSession`, модели блока) и `core:speech` (`Speaker`, `HandsFreeSettings` в конструкторах VM экранов шагов).
- `voice/` — режим «Руки заняты» (задача `.claude/tasks/hands-free.md`, макет `design/features/hands-free`):
  - Фразы: `VoicePhrase(lines, mode)` из `VoiceText` (`Res` — строка `core/localization` с аргументами, в т. ч. вложенными `VoiceText`; `Raw` — текст из данных, задание SDK); первая строка — в `mode` (FLUSH — новый шаг, QUEUE — итог), остальные — следом. `Speaker.say(phrase)` берёт строки `getString` и ставит их подряд; `VoiceText.text()` — та же строка в composable (экран и озвучка берут текст из одного места).
  - `Speaker.follow(enabled, states, phrase)` — озвучка экрана: при включённом флаге каждое значение `states` сравнивается с предыдущим (`phrase(previous, current)`; первое — с `null`: включили озвучку или вернулись на экран — звучит текущий шаг), выключение — `stop()`. VM экрана зовёт её в `onStart` через `intent { repeatOnSubscription { … } }` (говорим, пока экран подписан на state), в `onCleared` — `speaker.stop()`. Решения «что сказать» — чистые функции рядом с VM (`BypassVoice.kt`, `CloneVoice.kt`, `CheckStateVoice.kt`, `FastMountVoice.kt`) с unit-тестами.
  - Кнопка «Озвучка»: `HandsFreeVoiceViewModel(speaker, settings)` — state `HandsFreeVoiceState` (голос `availability`, флаг, `speaking`, подсказка `tip`, лист «Нет голоса» `noVoiceHelp`; `mode` — OFF / ON / SPEAKING / NO_VOICE, `null` — кнопки нет: синтеза нет или голос ещё не проверен), интенты `onToggle` (нет голоса — открыть «Нет голоса»; первое включение — подсказка, `markTipShown`, сама гаснет через 7 с), `onTipDismiss`, `onNoVoiceDismiss`, `onInstallVoice` (`Speaker.openVoiceInstall`). `rememberHandsFreeVoice()` (`koinViewModel`, одна VM на запись навигации) → `HandsFreeVoice(state, actions)`; `HandsFreeVoiceButton(voice)` — в `actions` `CmpTopAppBar`: круг 48 dp (выкл — обводка `VolumeOff`, вкл — заливка `VolumeUp`, говорит — `GraphicEq` + расходящееся кольцо 1,6 с; «Убрать анимации» — масштаб длительности Compose, нет голоса — обводка и красная точка), подсказка — `Popup` под кнопкой, «Нет голоса» — нижний лист (< 600 dp окна, `LocalWindowInfo`) или `CmpDialog`; тексты по платформе — `VoiceSettingsHelp` (`expect platformVoiceSettingsHelp`): Android — «Установить голос» (если `canInstall`) / «Позже», iOS — путь в настройках, desktop — пути Windows и macOS; строки — `deviceinteraction_voice_*`. `testTag`: `handsfree_voice`, `handsfree_voice_tip_ok`, `handsfree_novoice`.
- `viewmodel/BaseDeviceViewModel<S, E>(deviceSession, initialState)` — база VM, работающих с подключённым блоком, поверх `BaseViewModel<S, E>` (правила VM действуют):
  - `connectedDevice` / `connectedDeviceName` — блок на связи (`Ready`) как поток для `collectIntoState`; `currentDevice` — снимок для интентов.
  - `launchOnDevice { }` — работа с блоком: без связи не стартует (`null`), при потере связи отменяется вся запущенная так работа (параллельные запуски не отменяют друг друга); `launchOnDevice(key) { }` — то же с заменой прежней работы по ключу (процесс экрана вместо поля `Job?`), отмена — `cancelLaunched(key)`. Слежение за связью стартует с первого вызова — `super.onStart()` звать не нужно.
  - Лямбда `launchOnDevice` получает `IntentScope` (`reduce`/`postSideEffect` доступны); `onEachDeviceReady`/`onDeviceLost` принимают обычные `suspend`-функции — `onDeviceLost(::onConnectionLost)` с хелпером `private suspend fun onConnectionLost() = subIntent { … }` (контекст — корутина подписки).
  - `onEachDeviceReady { }` (на каждое (пере)подключение, отменяется при потере связи) и `onDeviceLost { }` (на каждый выход сессии из `Ready`, в т.ч. если VM создана до подключения) — вызывать из `onStart()`; живут, пока жива VM (не только пока экран подписан на state).
  - Необработанные исключения логируются, как у `intent`.
- `components/ConfigurationKit.kt` — общие компоненты конфигураций (`ModelBadge`, `ReadOnlyBadge`, `SourceTag`, `ConfigurationOptionRow`, `ConfigurationOptionsPanel`, форма `ConfigurationInfoDialog` с ограничениями `LocalConfiguration` — отсюда зависимость на `feature:configurator`): редактор настроек (`settings-ui`) и экраны конфигуратора (`configurator-ui`).
- `platform/SettingsFiles.kt` — порты файлов настроек `.dxs` (`SettingsFilePicker`/`SettingsFileSaver`, заглушки `NoSettingsFile*`, `settingsFileName`); реализации — `composeApp/filepicker/RememberSettingsFiles.kt`. Konsist `capability-usage` пускает их в presentation любой фичи.
- `navigation/ConfigurationPickRequest(kind, deviceName, firmwareCanCode)` — запрос «Загрузить из…» редактора блока к экранам конфигуратора (слот `configurationPicker`).
- `pin/ServicePinDialog(message, ServicePinDialogState, …, testTagPrefix)` — диалог PIN программирования (BLE), общий для прошивки и режима программирования; строки — `deviceinteraction_pin_*` в `core/localization`.
