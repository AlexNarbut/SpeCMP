# feature/auth-state

- Стартовая логика приложения: определяет, какая зона видна (`WAITING` / `NO_AUTH` / `AUTHED` / `CHECK_FAILED`).
- `AuthState` — enum состояния сессии.
- `AuthStateRepository` — session-операции поверх Specialist SDK: `observeIsLoggedIn(): Flow<Response<Boolean>>` и `logout()`. Другие фичи не оборачивают session-методы SDK сами, а подключают этот репозиторий.
- Логаут выполняется только через `LogoutUseCase` (вызов `logoutUseCase()`, `operator fun invoke`): он вызывает `logout()` и после успеха проходит по всем зарегистрированным в DI `AuthCloseable` (`core:common`), вызывая `release()` — app-scoped синглтоны (чат-репозиторий и будущие холдеры сессий) так чистят состояние при смене аккаунта. ViewModel не вызывают `AuthStateRepository.logout()` напрямую.
- `observeIsLoggedIn()` — подписка на `listenAuthFlowUseCase` SDK: состояние из хранилища токенов, меняется в момент входа и выхода (без опроса и ручных «перепроверок»). `Waiting` SDK пропускается — загрузку показывает VM. Выход в SDK (с 2026-10-27, `alarmtrade-common3` dev) стирает токены сразу, а сервер уведомляет в фоне с сохранённым токеном — экран входа появляется без ожидания сети.
- `AuthStateViewModel` маппит flow в `AuthState`; ошибка проверки — `CHECK_FAILED`, `onRetry()` перезапускает проверку (`launchReplacing`, на время повторной проверки — `WAITING`). Подписка живёт всю жизнь VM (из `onStart()`, не `collectIntoState`): перезапуск при уходе в фон открыл бы новую сессию авторизованной зоны.
- `AuthStateNavGraph(waitingState, noAuthState, authedState, errorState)` — composable-переключатель зон с fade-анимацией; это и есть «навигация» между зонами. Экраны не навигируют между зонами сами: login/logout меняют состояние сессии, граф подхватывает. `errorState` получает `onRetry`; готовый экран — `SessionCheckErrorScreen` (строки модуля в `composeResources`, ключи `authstate_root_*`).
